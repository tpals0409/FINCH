  • 알림함(메일) 전체 — contracts.md P23. 목록 조회도 읽음 처리도 엔드포인트가 없다. 아트보드 22~24 의 항목 종류·요약·미읽음 개수는 PRD 문구에서 옮긴 요청 사항이고 응답 스키마가 아니다. GitLab 이슈 #26 ①번 회신 대기.
  • 위키의 "맞아요" 승격 — contracts.md P24. ai_inferred 항목을 사실로 승격하는 경로가 없다. 그래서 아트보드 16 에 "맞아요" 버튼을 그리지 않았다 — 그리면 눌러도 아무 일도 안 일어나는 죽은 버튼이 된다. 반대쪽("아니에요")만 DELETE /ai/wiki/facts/{factId} 로 성립하는데, 한쪽만 있는 맞다/아니다는 "아니오만 고를 수 있는 질문" 으로 읽히므로 확인 UI 를 짝으로 만들지 않고 기존 삭제 컨트롤 하나로 뒀다. GitLab 이슈 #26 ②번 회신 대기.
  • 브리핑 전체 화면의 존재 자체 — ia.md §1. PRD v1.0 §06 의 화면 집계에 독립 항목으로 없다. GET /ai/briefing 은 확정 계약이지만 그 응답을 전체 화면으로 펼칠지가 잠정이다. 홈의 브리핑 블록만으로 끝날 수도 있다.
라우트 이름이 두 문서에서 어긋난다 — 코드를 따랐다. ia.md §1 은 화면 이름을 "메일", 라우트를 /mail 로 적었지만 frontend/src/shared/config/routes.ts 는 inbox: '/inbox' 이고 "프로토타입을 보고 /mail 로 되돌리지 않는다" 를 주석으로 못박았다. contracts.md P23 도 "알림함(/inbox)" 으로 등재돼 있다. 둘 다 미확정이므로 이 캔버스는 코드 쪽(/inbox)을 쓰고 화면 제목은 "알림함" 으로 적는다. 확정이 오면 고칠 자리는 routes.ts 한 줄과 이 캔버스의 아트보드 22~24 다.
AI 슬롯 배치를 새로 정하지 않았다. ia.md §4 가 이미 정한 것을 화면으로 옮겼을 뿐이다. 이 축에 들어오는 슬롯은 2종이다 — 6번(Ask My Portfolio, AI 채팅 화면 전체)과 1번(데일리 브리핑)이다. 나머지 4종(수익률 원인 분석 · 종목 분석 · 주문 전 점검 · 포트폴리오 진단)은 다른 축의 화면에 들어간다.
  • 6종 전부 일반 요청/응답이다. SSE 는 폐기됐다 (ia.md 개정 전제 1). 아트보드 11 의 대기 상태는 타이핑 연출이 아니라 단발 응답을 기다리는 로딩이다. 글자가 한 자씩 나오는 화면을 그리지 않았다.
  • 근거 목록(citations)은 접거나 생략하지 않는다. 응답 봉투의 최상위 키라 슬롯 6종 전부에 실린다. engine·wiki 는 외부 URL 이 없어 테두리 뱃지 + 화살표 없음으로 구분했다 — 채움 뱃지와 같은 모양이면 "출처가 있는 척" 이 된다 (ia.md §4 근거 표시).
  • 피드백 슬롯은 requestId 하나 = 슬롯 하나. 채팅은 답변 말풍선마다, 브리핑은 블록 하단에 하나다. 브리핑 items[] 마다 붙이지 않는다. 붙는 자리 수 자체는 회신 대기(6 vs 3 vs 8)이고 이 캔버스는 ia.md §4 표를 따랐다.
  • 캐릭터(핀치·블루치)는 AI 슬롯과 그 빈 상태·에러 자리에만 올 수 있다. 이 캔버스에서 해당하는 자리는 아트보드 9(채팅 빈 상태) · 13·14(채팅 에러) · 17(위키 빈 상태) · 27(브리핑 빈 상태) 다섯이다. 와이어프레임 단계라 에셋을 넣지 않고 자리만 비웠다 — 자산 요약 숫자·주문·충전 확인에는 넣지 않는다.
AI 는 판단을 대신하지 않는다. 이 캔버스의 AI 문구에는 매수·매도 권유, 목표주가, 투자의견, "좋다/나쁘다" 판정이 없다. "긍정 요인 / 부정 요인" 같은 표현도 쓰지 않는다 — AI 명세 §2 가 출처 귀속형("시장이 주목하는 요인", "공시·실적에서 확인된 위험 요인")으로 고정했고 규제 대응이라 화면에서 되돌리면 안 된다. disclaimer 는 모든 AI 응답 자리에 노출한다 (apiSpec §10.3 보존 4종).
응답은 백엔드 형식으로 온다. 백엔드가 AI 의 snake_case + 봉투를 벗겨 camelCase + 봉투 없음으로 재포장한다 (apiSpec §10.3). 그래서 이 캔버스의 ab-api 줄은 requestId·dataAsOf·relatedTickers 로 적혀 있다 — AI 명세의 request_id·data_as_of·related_tickers 를 그대로 옮기지 않았다. 필드 이름 자체는 바뀌지 않는다 — ticker 를 stockCode 로 바꾸지 않는다(경로 파라미터만 그렇다).
토큰을 새로 만들지 않았다. 이 캔버스의 모든 색·반경·그림자·타이포는 기존 역할 토큰으로 해결된다. 판단이 들어간 자리는 넷이다.
  • AI 표면에 "AI 색" 을 쓰지 않는다. bg-layer-default + stroke-neutral-weak + shadow-ai + radius-ai(18px). 일반 카드는 stroke-neutral-subtle · 그림자 없음 · radius-card(16px) 이라 획 무게 · 깊이 · 반경 셋이 한꺼번에 달라진다. AI 카드에 브랜드 마크를 붙이지 않는다.
  • 계약·근거가 없는 블록은 점선 + 그림자 없음. 새 토큰이 아니라 형태다 (tokens.css §5 주석). ai_inferred 태그도 같은 이유로 점선이다 — 단정형이 아님을 색이 아니라 형태로 말한다.
  • 에러에 등락 적색을 쓰지 않는다. bg-critical-weak 면 + fg-critical(잉크) bold + 아이콘. 적색이면 "떨어졌다" 로 오독된다 (finch-seed §4).
  • 등락은 브리핑 항목 본문에만 나온다. segments[].direction 이 up·down 인 조각만 fg-up·fg-down(700 단계) 로 칠하고 부호가 반드시 같이 온다. 13~15px 본문이라 -vivid(600)를 쓰지 않는다 — 18px 이상 굵은 가격에만 쓴다. 숫자를 정규식으로 찾아 칠하지 않는다.
카카오 로그인 버튼의 #FEE500 이 이 캔버스의 유일한 토큰 밖 색이다. 카카오 브랜드 가이드가 강제하는 색이라 토큰화하지 않는다 — Button.tsx 의 bg-[#FEE500] 과 같은 예외이고 팔레트 유출 검사에서도 이것만 통과시킨다.

자체 회원가입 폼이 없다. 인증 수단은 카카오 OAuth 2.0 단일이고 서버가 최초 로그인 시 계정·계좌·초기 예수금을 함께 만든다 (apiSpec §2.1). 이전 판의 /signup 화면은 ia.md 에서 삭제됐다 — 되살리지 않는다.

이 화면에는 에러 상태가 없다. 부를 API 가 없기 때문이다. 인가 실패는 카카오 화면에서 일어나거나 콜백(/oauth/kakao)으로 돌아온 뒤에 드러난다 — 아트보드 4 가 그 자리다. 빈 상태도 없다 — 표시할 데이터가 없는 화면이다.

미인증 접근이 ?redirect= 를 들고 여기로 온다 (ia.md §1). 화면에는 아무 표시도 하지 않는다 — "로그인이 필요합니다" 를 띄우면 처음 방문한 사람에게 실패로 읽힌다. 세션 복구 실패 코드 두 가지 중 AUTH_REFRESH_TOKEN_MISSING(쿠키 없음)은 조용히 비로그인으로 다루는 것이 계약이다 (apiSpec §2.2).

POST /auth/kakao → GET /users/me → 홈
로그인 중입니다 잠시만 기다려 주세요
이 화면은 로딩 상태가 곧 기본 상태다. 성공하면 홈으로 떠나므로 사용자가 머무는 정상 화면이 아니다. 그래서 내비도 탭바도 그리지 않았다 — 뒤로 갈 곳이 없고, 탭을 누를 시간도 없다.

빈 상태가 없다. 인가 코드가 없으면 그건 빈 상태가 아니라 에러다(아트보드 4).

성공 시 화면에 "성공" 을 그리지 않는다. 완료 화면을 만들면 사용자가 한 번 더 눌러야 홈에 간다. Set-Cookie: refreshToken 은 헤더로만 오고 accessToken 은 메모리에 둔다 (apiSpec §1.2·§2.1) — 화면에 표시할 것이 없다.

문구는 서버가 완성해서 내려준다 (apiSpec §1.3). 화면이 코드별 문구를 다시 만들지 않는다. 이 화면이 다룰 코드는 AUTH_KAKAO_FAILED(401) 하나다 — apiSpec §2.1 의 에러 표에 그것만 있다.

재시도 버튼을 두지 않고 로그인 화면으로 보낸다. 인가 코드는 일회용이라 같은 코드로 다시 부르면 반드시 또 실패한다. "다시 시도" 버튼은 눌러도 안 되는 버튼이 된다.

등락 적색을 쓰지 않았다. bg-critical-weak(gray-300) 면 + fg-critical(잉크) bold + 아이콘 + 문구. 색만으로 알리지 않는다 (finch-seed §4).

설정 화면을 흡수한 자리다 (ia.md §1 기타). 테마·로그아웃만 있는 화면을 따로 두면 사용자가 어느 쪽에 무엇이 있는지 외워야 한다. 계좌 초기화 진입점은 없다 — GitLab 이슈 #27 로 기능 자체가 빠졌고 POST /account/reset 은 apiSpec v0.7 에서 삭제됐다. 되살리지 않는다.

profileImageUrl 은 null 일 수 있다 (apiSpec §2.4). 카카오의 선택 동의 항목이라 동의하지 않으면 값이 없고, 빈 문자열이 아니라 null 이다. 이 아트보드가 그 기본 아바타 상태다 — <img src=""> 는 브라우저가 현재 페이지를 다시 요청하게 만든다.

로그아웃을 다른 진입 행과 같은 무게로 두지 않았다. 목록을 끊어 별도 블록으로 뒀다 — 오탭하면 세션이 날아간다. 색으로 위험을 알리지 않고 블록 분리로 알린다(확인은 아트보드 7).

미읽음을 점 하나로 알리지 않는다. 개수 뱃지(3)를 함께 둔다 — 점만 있으면 몇 건인지 알 수 없어 사용자가 매번 열어 확인한다. 다만 이 개수의 출처가 없다 — 알림함 계약이 없어서다(P23, 아트보드 22).

AI 플로팅 버튼이 없다. PRD 가 정한 배치(종목 상세 · 포트폴리오 · 브리핑 · 뉴스 상세)와 프로토타입의 실제 배치(홈 · 종목 상세 · 포트폴리오 · 브리핑) 어느 쪽에도 마이페이지가 없다 (ia.md §3).

탭바와 내비는 골격으로 만들지 않는다. 이미 아는 값이고, 골격으로 바꾸면 탭이 눌리지 않는 것처럼 보인다. 로그아웃 행도 골격으로 둔다 — 프로필이 아직 안 온 상태에서 로그아웃만 눌리게 하면 어느 계정을 로그아웃하는지 모르는 채로 누른다.

이 화면의 에러 상태는 그리지 않았다 — 도달할 수 없다. GET /users/me 는 앱 부팅 시 세션 복구에 이미 한 번 쓰이고(apiSpec §2.4), 실패하면 그 단계에서 /login 으로 보내진다. 마이페이지에 들어온 시점에는 값이 캐시에 있다. 도달 가능한 실패는 POST /auth/logout 쪽이고, 로그아웃은 실패해도 클라이언트 토큰을 버려 비로그인으로 떨어지므로 에러 화면 대신 로그인 화면이 결과다.

로그아웃할까요?
보유 종목과 예수금은 그대로 남습니다. 다시 카카오로 로그인하면 이어서 볼 수 있습니다.
파괴적 확인 버튼의 채움도 주요 버튼과 같은 잉크다. 모노톤에 위험 solid 면을 두지 않았기 때문이다 (tokens.css §3 주석 — bg-critical-solid 를 만들지 않은 이유). 구분은 문구가 한다.

"데이터가 지워집니다" 로 쓰지 않는다. 로그아웃은 원장을 건드리지 않는다 — POST /auth/logout 은 Refresh Token 만 무효화한다(apiSpec §2.3). 지워지지 않는 것을 지워진다고 적으면 사용자가 로그아웃을 못 한다.

확인 자체는 필요하다. Access Token 이 메모리에만 있어 로그아웃하면 그 자리에서 세션이 끊긴다 — 되돌리려면 카카오 인가를 다시 통과해야 한다.
아트보드 8 · 404
없는 경로
라우트 * · API 없음
페이지를 찾을 수 없습니다 주소가 바뀌었거나 없는 화면입니다
브리핑의 deeplink 가 조용히 404 가 되는 자리다. deeplink 는 AI 서버가 만든 프론트 경로 문자열이고(예: /stocks/000660?tab=ai), 라우트를 바꾸면 화면에 에러도 안 뜨고 그냥 이 페이지로 온다 (ia.md §2). 그래서 "이전 화면으로" 를 함께 둔다 — 브리핑에서 눌러 왔다면 목록으로 돌아갈 길이 있어야 한다.

404 에 검색창을 넣지 않는다. 탐색 탭이 이미 그것이고, 여기서 검색시키면 잘못된 링크를 사용자가 스스로 고치게 만드는 화면이 된다.

탭바를 그리지 않았다. 없는 경로는 어느 탭에도 속하지 않는다 — 탭을 그리면 어느 탭이 현재인지 정할 수 없고, 아무 탭도 켜지지 않은 탭바는 고장으로 읽힌다.

로딩·에러·빈 상태가 없다. 이 화면 자체가 다른 화면들의 최종 에러 상태다.
