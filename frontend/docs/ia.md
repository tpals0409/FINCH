# 프론트엔드 화면 목록·IA

이 문서는 프론트엔드가 만들 화면의 목록과 구조를 정한다.
역할 분담과 일정 산정의 기준이 되므로 **분담 가능한 단위**로 쪼개 적었다.

- 작성일: 2026-08-19
- UI 레퍼런스: 토스증권 / 플랫폼: 모바일 웹(반응형, 모바일 우선)
- 관련 문서: [`../../docs/convention/frontConvention.md`](../../docs/convention/frontConvention.md)

백엔드 API가 확정되지 않은 항목은 `(미확인)`으로 남겼다.
**빈칸으로 두지 않고 무엇이 미확인인지 적는다.** 나중에 답이 왔을 때 채울 자리가 보여야 한다.

## 1. 화면 목록

`AI` 열은 AI 슬롯이 들어가는 화면을 표시한다. 슬롯 상세는 §4에 있다.

### 인증

| 화면     | 라우트    | 목적      | 필요한 API                                  | AI  | 의존 |
| -------- | --------- | --------- | ------------------------------------------- | --- | ---- |
| 로그인   | `/login`  | 세션 획득 | 로그인 (미확인 — 팀 질문 ③)                 |     | —    |
| 회원가입 | `/signup` | 계정 생성 | 회원가입 (미확인 — 지원 여부부터 확인 필요) |     | —    |

로그인 이후 화면은 전부 인증이 필요하다. 미인증 접근은 `/login`으로 보내고, 원래 가려던 경로를 쿼리 파라미터로 들고 가 로그인 후 되돌린다.

### 홈·자산

| 화면       | 라우트       | 목적                                            | 필요한 API                     | AI    | 의존   |
| ---------- | ------------ | ----------------------------------------------- | ------------------------------ | ----- | ------ |
| 홈         | `/`          | 총자산·손익 요약, 보유 종목 요약, 오늘의 브리핑 | 계좌 요약, 보유 종목, 시세     | ● 2종 | 로그인 |
| 포트폴리오 | `/portfolio` | 보유 종목 상세, 비중, 손익, 진단                | 보유 종목, 평가손익, 진단      | ● 2종 | 로그인 |
| 거래 내역  | `/orders`    | 주문·체결 내역 조회                             | 주문 내역 (미확인 — 팀 질문 ⑥) |       | 로그인 |

홈과 포트폴리오는 데이터 출처가 겹친다. **같은 쿼리 키를 공유**해 두 화면이 서로 다른 값을 보여주는 일이 없게 한다.

### 탐색·거래

| 화면      | 라우트                  | 목적                       | 필요한 API                              | AI    | 의존              |
| --------- | ----------------------- | -------------------------- | --------------------------------------- | ----- | ----------------- |
| 종목 검색 | `/search`               | 종목명·코드로 찾기         | 종목 마스터 검색 (미확인 — 팀 질문 ⑥)   |       | —                 |
| 종목 상세 | `/stocks/:ticker`       | 시세·차트·기업정보·AI 분석 | 종목 정보, 시세, 일봉, 실시간 시세      | ● 1종 | —                 |
| 주문      | `/stocks/:ticker/order` | 매수·매도 실행             | 주문 생성, 주문 가능 금액               | ● 1종 | 로그인, 종목 상세 |
| 관심종목  | `/watchlist`            | 담아둔 종목 시세 확인      | 관심종목 조회·등록 (미확인 — 팀 질문 ⑥) |       | 로그인            |

## 2. 라우트 트리와 URL 상태

```
/                          홈
/login                     로그인
/signup                    회원가입
/search                    종목 검색
/stocks/:ticker            종목 상세
/stocks/:ticker/order      주문
/portfolio                 포트폴리오
/orders                    거래 내역
/watchlist                 관심종목
/chat                      AI 채팅
/settings                  설정
*                          404
```

### 쿼리 파라미터로 둘 상태

컨벤션 §4가 "새로고침·공유·뒤로가기에서 살아 있어야 하는 것은 전부 URL"이라고 정했다.
모바일에서는 뒤로가기를 훨씬 자주 쓰므로 탭 선택을 `useState`에 두면 바로 티가 난다.

| 경로                    | 파라미터   | 값                                   |
| ----------------------- | ---------- | ------------------------------------ |
| `/stocks/:ticker`       | `tab`      | `chart` \| `info` \| `ai`            |
| `/stocks/:ticker`       | `period`   | `1D` \| `1W` \| `1M` \| `3M` \| `1Y` |
| `/stocks/:ticker/order` | `side`     | `buy` \| `sell`                      |
| `/portfolio`            | `tab`      | `holdings` \| `diagnosis`            |
| `/orders`               | `status`   | `all` \| `pending` \| `filled`       |
| `/search`               | `q`        | 검색어                               |
| `/login`                | `redirect` | 로그인 후 돌아갈 경로                |

**주문 입력값(수량·가격)은 URL에 두지 않는다.** 공유될 값이 아니고, 잘못 공유되면 남의 주문 화면이 채워진 채 열린다.

## 3. 화면 간 이동

### 하단 탭바 — 4개

```
홈  |  탐색  |  포트폴리오  |  AI
/      /search   /portfolio    /chat
```

탭을 5개 이상 두면 모바일에서 터치 영역이 좁아진다(컨벤션 §9의 44×44px 기준).
관심종목과 거래 내역은 탭에 두지 않고 홈·포트폴리오 안에서 들어간다.

### 주요 흐름

```
로그인 → 홈
홈 → 보유 종목 탭 → 종목 상세 → 주문 → 체결 → 거래 내역
탐색 → 검색 → 종목 상세 → 관심종목 담기
포트폴리오 → 진단 탭 → (AI 진단 결과) → 종목 상세
AI 채팅 → 답변 속 종목 언급 → 종목 상세
```

**종목 상세가 허브다.** 거의 모든 화면에서 여기로 들어온다.
그래서 종목 상세는 진입 경로와 무관하게 혼자 성립해야 한다 — 이전 화면의 상태를 props로 받아 쓰지 않는다.

### 주문을 별도 라우트로 둔 이유

토스증권은 주문을 바텀시트로 띄운다. 그런데 주문은 **뒤로가기로 빠져나갈 수 있어야 하고**, 실패했을 때 되돌아올 지점이 필요하다.
라우트로 두면 뒤로가기가 자연스럽게 처리되고 `redirect` 파라미터로 로그인 후 복귀도 된다.
화면 표현은 바텀시트로 하되 **주소는 갖는다.**

## 4. AI 슬롯 배치

AI 명세는 "화면에서 AI 응답이 들어갈 빈 슬롯"만 요구한다. 위치는 프론트가 정한다.

| #   | 기능             | 화면            | 위치                         | 전송 방식 |
| --- | ---------------- | --------------- | ---------------------------- | --------- |
| 1   | 데일리 브리핑    | 홈              | 자산 요약 아래 첫 블록       | 일반 요청 |
| 2   | 수익률 원인 분석 | 홈 · 포트폴리오 | 손익 숫자 바로 아래          | 일반 요청 |
| 3   | AI 종목 분석     | 종목 상세       | `tab=ai` 탭                  | **SSE**   |
| 4   | 주문 전 점검     | 주문            | 주문 확인 단계, 제출 버튼 위 | 일반 요청 |
| 5   | 포트폴리오 진단  | 포트폴리오      | `tab=diagnosis` 탭           | 일반 요청 |
| 6   | Ask My Portfolio | AI 채팅         | 화면 전체                    | **SSE**   |

### 슬롯 공통 규약

- 슬롯은 **위젯 단위 에러 경계**를 갖는다(컨벤션 §8). AI가 실패해도 그 화면의 나머지는 살아 있어야 한다
- 슬롯이 비어 있는 상태(아직 요청 전)와 로딩 상태를 구분해 표시한다
- 2번은 홈과 포트폴리오 양쪽에 들어간다. **컴포넌트를 두 번 만들지 않는다** — 한쪽 feature에 두고 다른 쪽이 재사용하거나, 겹치면 `shared`로 올린다
- 3번·6번은 SSE다. `EventSource`를 쓸 수 없다(POST라서). 파서는 `shared/api`에 하나만 둔다

## 5. 화면 ↔ feature 매핑

컨벤션 §2의 `features/` 구조에 대응시킨다. **feature는 라우트가 아니라 도메인 단위로 나눈다.**

| feature     | 담당 화면        | 주요 내용                                  |
| ----------- | ---------------- | ------------------------------------------ |
| `auth`      | 로그인, 회원가입 | 세션, 토큰, 라우트 가드                    |
| `home`      | 홈               | 자산 요약, 브리핑 슬롯                     |
| `stock`     | 검색, 종목 상세  | 종목 정보, 시세, 차트, 종목 분석 슬롯      |
| `order`     | 주문, 거래 내역  | 주문 폼, 검증, 주문 전 점검 슬롯           |
| `portfolio` | 포트폴리오       | 보유 종목, 손익, 진단 슬롯, 원인 분석 슬롯 |
| `chat`      | AI 채팅          | SSE 스트리밍 대화                          |
| `watchlist` | 관심종목         | 담기·해제, 목록                            |

### 여러 feature가 필요한 것 → `shared`

- 시세 구독 관리자 — `stock` `home` `portfolio` `watchlist`가 전부 쓴다
- SSE 파서 — `stock` `chat`이 쓴다
- 종목 시세 표시 컴포넌트(종목명 + 현재가 + 등락률) — 네 화면에서 반복된다
- 금액·비율·등락 포매터

**시세 구독 관리자와 종목 행 컴포넌트가 가장 자주 재구현될 후보다.** 분담 전에 한 명이 먼저 만든다.

## 6. 분담 후보 묶음

두 덩이로 묶었다. 기준은 셋이다 — **AI 슬롯이 한쪽에 몰리지 않을 것, 학습 부담이 갈릴 것, feature 폴더가 겹치지 않을 것.**

### A · 거래 축

| 화면             | feature |
| ---------------- | ------- |
| 종목 검색        | `stock` |
| 종목 상세 · 차트 | `stock` |
| 주문             | `order` |
| 거래 내역        | `order` |

AI 슬롯 2종(종목 분석 SSE, 주문 전 점검).
기술 부담: lightweight-charts, 주문 폼 Zod 검증, 실시간 시세 구독.

### B · 자산 축

| 화면       | feature     |
| ---------- | ----------- |
| 홈         | `home`      |
| 포트폴리오 | `portfolio` |
| AI 채팅    | `chat`      |
| 관심종목   | `watchlist` |

AI 슬롯 4종(브리핑, 원인 분석 ×2, 진단, 채팅 SSE).
기술 부담: SSE 스트리밍 UI, 진단 지표 SVG 그래프.

### 슬롯 개수가 안 맞는 것에 대해

B가 4종, A가 2종이다. 다만 **A의 종목 상세 SSE와 B의 채팅 SSE가 같은 파서를 쓰므로** 실제 구현량은 슬롯 수만큼 차이 나지 않는다.
B의 원인 분석은 홈·포트폴리오 양쪽에 들어가지만 컴포넌트는 하나다.
차트가 A에 통째로 들어가는 것이 무게를 맞춘다.

### 분담 전에 공동으로 끝낼 것

여기 합의 없이 갈라지면 **같은 컴포넌트가 두 개 생긴다.**

1. `auth` — 로그인 없이는 양쪽 다 화면을 못 본다. 한 명이 먼저 끝낸다
2. `shared/api` — HTTP 클라이언트, SSE 파서, 429 정책, 인증 인터셉터
3. `shared/ui` 코어 — Button, BottomSheet, Skeleton, ErrorBoundary
4. 디자인 토큰 — 등락 의미 토큰 포함
5. 시세 구독 관리자
6. 종목 시세 행 컴포넌트

### 소유 경계

- `features/` 하위 폴더는 **한 사람 단독 소유**한다
- `shared/`는 **공동 소유**다. 여기를 건드리는 MR은 상대가 리뷰한다
- 상대 feature의 것이 필요하면 직접 import하지 않는다(ESLint가 막는다). `shared`로 올리자고 제안한다

## 7. 미확인 항목

답이 오면 이 문서를 갱신한다. 갱신하지 않으면 문서가 거짓말이 된다.

| 항목                                      | 영향받는 화면                  | 팀 질문 |
| ----------------------------------------- | ------------------------------ | ------- |
| 인증 방식 (JWT 발급·만료·저장·401 흐름)   | 전 화면                        | ③       |
| 회원가입 지원 여부                        | 회원가입                       | ③       |
| 종목 마스터 조회 API 존재 여부            | 검색, 종목 상세                | ⑥       |
| 관심종목 API 존재 여부                    | 관심종목                       | ⑥       |
| 일봉 히스토리 API 출처 (백엔드 / AI 서버) | 종목 상세 차트                 | ⑥       |
| 거래 내역 API 존재 여부                   | 거래 내역                      | ⑥       |
| 시세 WebSocket 동시 구독 슬롯 수          | 홈, 포트폴리오, 관심종목, 검색 | ④       |

**같은 데이터를 백엔드와 AI 서버 양쪽에서 받으면 화면마다 값이 어긋난다.** 출처를 하나로 정해야 한다.

시세 슬롯 수는 인프라 서버 대수에 따라 정해진다고 들었다. 그 수가 정해지기 전까지 구독 관리자는
**슬롯 수를 상수 하나로 두고 초과분을 폴링으로 내리는 구조**로만 만들어 둔다. 숫자가 오면 상수만 바꾼다.
