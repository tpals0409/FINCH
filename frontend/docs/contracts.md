# 계약 현황

프론트가 의존하는 크로스파트 계약이 **어디까지 확정됐고 무엇을 기다리는지** 한곳에 모은 문서다.

이 문서의 목적은 다음 작업자와 에이전트가 원본 문서를 다시 읽지 않고도
무엇이 정해졌는지 알게 하는 것이다. **규약의 본문은 여기가 아니라 원본에 있다.**
값이 어긋나면 원본이 진실이다.

- 기준일: 2026-08-24 (AI 위키 화면·피드백 슬롯 등재에서 나온 미확정 5건 추가)
- 참조 원본
  - [`docs/api/apiSpec.md`](../../docs/api/apiSpec.md) — 백엔드 API 명세 **v0.2 (확정판).**
    이 문서가 **단일 기준**이다. 절 번호 표기 `§`는 별도 표시가 없으면 이 문서를 가리킨다
  - [`docs/spec/featureSpec.md`](../../docs/spec/featureSpec.md) — 기능 명세서 v2.1
  - [`ai/docs/api-spec.md`](../../ai/docs/api-spec.md) — AI 파트 인터페이스 계약. **AI 계열은 이 파일이 기준이다**
  - [`ai/docs/openapi.json`](../../ai/docs/openapi.json) — AI 서버의 실제 구현 스키마.
    AI 파트 문서와 어긋나면 구현이 맞고 문서가 틀린 것이다
  - GitLab 이슈 [#1](https://lab.ssafy.com/s15-fintech-finance-sub1/S15P21A101/-/issues/1) 회신 (19문항, 닫힘)
- 관련 규약: [`docs/convention/frontConvention.md`](../../docs/convention/frontConvention.md) (크로스파트) ·
  [`frontConvention.md`](./frontConvention.md) (프론트 내부) · [`ia.md`](./ia.md) (화면 목록)

> **공통 API 규격 v0.3은 기준에서 폐기됐다.** 값이 같아도 근거를 v0.3으로 적으면
> 다음 사람이 폐기된 문서를 다시 찾아 읽는다. 이 문서의 근거 열은 전부 `apiSpec.md` 기준으로 바꿨다.

**이 문서는 확정 / 잠정 확정 / 미확정 / 충돌의 네 단계를 쓴다.**
잠정 확정은 회신이 없어 프론트가 임의로 정하고 진행하는 것이다. 확정이 아니다.
**팀 회신이 오면 그 값이 우선하고 잠정 확정 항목은 폐기한다.**

### 1.4 시세

| #   | 항목                     | 확정된 값                                                                                                                                                                                                                                                                                                                                     | 출처                       |
| --- | ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| C33 | 실시간 시세 전달 방식    | **웹소켓(STOMP) + REST 폴링 폴백.** 두 경로의 시세 페이로드 스키마는 동일하다                                                                                                                                                                                                                                                                  | §5.6                       |
| C34 | 프론트 폴링 선행 구현    | **승인됨.** 폴링은 임시 코드가 아니라 최종 구조의 폴백 경로다. 단 `subscribe(stockCode, cb)` / `unsubscribe(stockCode)` 추상화 뒤에 숨기고 그 뒤에서 STOMP 클라이언트로 교체한다                                                                                                                                                                | §5.6                       |
| C35 | KIS 한도와 구독 범위     | **KIS 등록 한도는 프론트 계약에 노출되지 않는다.** 백엔드 수집 계층이 흡수한다 — 관심도 상위 종목만 KIS 실시간에 등록하고 나머지는 백엔드가 KIS REST를 폴링해 하나의 시세 캐시에 동일 스키마로 적재한다. **프론트는 종목이 어느 티어인지 알 수 없고 신선도 차이는 `asOf`로만 드러난다.** 화면에 보이는 종목만 구독하고 관심 종목을 상시 구독하지 않는다는 규칙은 유지하되 **이유가 바뀌었다** — 슬롯 한도를 프론트가 관리하기 때문이 아니라, 아무도 보지 않는 구독과 폴링 요청을 만들지 않기 위한 것이다 | §5.6                       |
| C36 | 슬롯 회수 주체           | **서버.** 종목별 마지막 관심 시각(STOMP 구독 존재 여부 또는 폴링 요청 시각) 기준으로 서버 전체 LRU로 배정·회수한다. **클라이언트의 해제 신호에 의존하지 않는 구조이므로 프론트는 `pagehide`·`visibilitychange` 등 이탈 이벤트에서 별도 신호를 보내지 않는다**                                                                                    | §5.6                       |
| C37 | 구독·해제 신호 채널      | **웹소켓은 STOMP 프레임 자체가 신호다** — `/topic/prices/{stockCode}` SUBSCRIBE가 구독, UNSUBSCRIBE 또는 연결 종료가 해제다. 별도 구독 메시지도 REST 신호 엔드포인트도 없다. **폴링은 무신호** — `GET /stocks/prices` 요청 자체가 관심 신호이고 TTL 경과가 해제다. 추상화 계층에서 `subscribe()`는 폴링 시작, `unsubscribe()`는 폴링 중단이다        | §5.6 · 이슈 #6             |
| C38 | 웹소켓 인증              | 핸드셰이크(`WS /ws`)는 **인증 없이 통과**시킨다. 인증은 **CONNECT 프레임의 `Authorization: Bearer {accessToken}` 헤더**에서 검증한다 — 브라우저 `WebSocket` 생성자가 커스텀 헤더를 붙일 수 없기 때문이다. **URL 쿼리로 토큰을 보내지 않는다**(로그 노출)                                                                                          | §5.6 · 이슈 #1 ⑬           |
| C39 | 하트비트                 | STOMP 내장 하트비트 **10초/10초 양방향**. **3회 미수신(30초)** 시 서버가 연결을 닫고 슬롯을 회수한다. 정상 종료는 disconnect 이벤트로 즉시 회수                                                                                                                                                                                                 | §5.6 · 이슈 #1 ⑪           |
| C40 | 폴링 주기                | **계약이 아니다.** 서버가 보장하는 것은 **폴링 티어 TTL 30초**뿐이고 주기는 프론트 재량이다. 권장값은 목록 화면 5초 · 주문 화면 3초이며, 관계식(**TTL ≥ 주기 × 4~6**)만 지키면 자유롭게 조정할 수 있고 조정 시 명세를 고칠 필요가 없다                                                                                                           | §5.6 · 이슈 #1 ⑪           |
| C41 | 다건 시세 조회           | `GET /stocks/prices?stockCodes=005930,000660` **쉼표 구분 문자열.** 파라미터 이름은 **`stockCodes`로 확정**(`codes`·`tickers` 아님). **한 번에 최대 50건.** 요청한 코드 중 존재하지 않는 것은 `items`에서 제외되고 전체 요청이 실패하지 않는다                                                                                                    | §5.5 · 이슈 #1 ②⑰          |
| C42 | `stale` 시세 스키마      | 세 상태다. **정상 수신**은 최신 값 + `stale: false`. **수신 끊김**은 `currentPrice`·`changeAmount`·`changeRate`가 **마지막 수신 값**, `asOf`가 마지막 수신 시각, `stale: true`. **값 없음(캐시 미스)**은 가격 3필드와 `asOf`가 **전부 `null`**, `stale: true`. 다건 조회는 **항목별로** 판정한다. 프론트는 `stale: true`면 "시세 지연"을 표시하고 값이 `null`이면 가격 영역을 비운다 | §5.4 · §5.5 · 이슈 #1 ⑩    |

### 그 외 관측한 것

- **`featureSpec` §10.2가 6종으로 정정됐다.** 이전 판이 "낡은 서술"로 다뤘던 충돌이 커밋 `ba3bf23`으로
  해소됐고, 프론트가 부르는 중계 경로까지 `/api/v1/ai/...`로 정확히 적혔다. GitLab 이슈 #9의 완료 판정이
  충족된 상태다(이슈는 열려 있다).
- **AI 서버에는 6종 밖에 `POST /feedback`과 위키 4종이 구현돼 있다.** 2026-08-24에
  `ia.md`가 "AI가 이해한 나" 화면과 피드백 배치 규칙을 등재해 **화면 범위가 정해졌다.**
  피드백은 `requestId` 하나가 슬롯 하나이고, 에러 봉투에도 `requestId`가 있으므로 실패 응답과
  `INSUFFICIENT_DATA` 대체 문구 자리에도 붙는다. 위키는 화면에서 `GET`·`PUT`·`DELETE` 셋만
  부르고 `POST /wiki/theses`는 AI 서비스가 스스로 호출한다. **이것이 P3(위키 중계 경로) 회신의
  선행 조건이었다** — `apiSpec.md` §10.1이 "프론트 화면 범위가 확정되면 추가한다"로 적혀 있다.
- **`429 RATE_LIMITED`는 AI 명세에 정의만 있고 세는 곳이 없어 현재 나가지 않는다.** 재시도 대기 로직을
  만들되 실제로 걸리는 것을 전제하지 않는다.
- **`ai/docs/api-spec.md`와 `ai/docs/openapi.json`이 벌어져 있다.** 어긋나면 구현(`openapi.json`)이 맞다.
- **AI 파트가 다른 파트에 요구하는 것은 둘뿐이다** — 서버 간 인증 수단과, 화면에서 AI 응답이 들어갈
  빈 슬롯이다. AI 명세 §11이 그렇게 적고 있다. 프론트가 만들 것은 슬롯이고, 그 안에 들어가는
  응답 내용의 책임은 AI 파트에 있다(C53).
