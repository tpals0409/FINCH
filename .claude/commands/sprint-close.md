## 1단계: 현재 상태 확인

다음을 **병렬로** 수행하세요:

2. [2] 섹션의 `start_commit` 을 확인하고 `git log --oneline {start_commit}..HEAD` 실행 (없으면 `git log --oneline -10`)
3. `git -C ~/Desktop/finch-gitops log @{upstream}..HEAD --oneline` 실행
   - 미푸시 커밋이 있으면 경고: "finch-gitops 에 미푸시 커밋 {N}건이 있습니다. push 후 진행하세요."

### 상태 가드
- `status: active` → 정상, 2단계로
- `status: idle` → [1] 완료 섹션과 MEMORY.md 표, 최신 Sprint ADR 을 대조:
  - **모두 일치** → "활성 스프린트가 없습니다. `/sprint-open` 을 먼저 실행하세요." 출력 후 **중단**
  - **불일치** (ADR 미생성 또는 MEMORY 미갱신) → "이전 종료가 중단된 것으로 보입니다. 누락된 단계부터 재개합니다." 출력 후 재개 (ADR 미생성 → 3단계, MEMORY 미갱신 → 5단계)

### 커밋 확인
git log 가 비어 있으면:
- "이번 스프린트에 커밋이 없습니다. 취소하시겠습니까?" 질문
- 취소 → `status` 만 `idle` 로 바꾸고 **종료** (윈도우/ADR/MEMORY 갱신 없음)
- 진행 → 2단계로 (빈 요약으로 최소 기록)

## 2단계: 자동 초안 + 사용자 확인

[2] 섹션과 git log 를 기반으로 **초안을 자동 생성**해 제시하세요:

```
## 스프린트 종료 초안

- **스프린트**: Sprint {N} — {제목}
- **작업 요약**: (커밋 기반 자동 추출)
  - {요약 1}
  - {요약 2}
- **이월 항목**: 없음 (또는 추정)

수정할 내용이 있으면 알려주세요. 없으면 "확인"이라고 답해주세요.
```

이어서 **다음 스프린트 정보만** 질문: 번호, 제목, 계획 작업 (또는 "미정")

## 3단계: Sprint ADR 생성

`docs/adr/sprints/sprint-{N}.md` 를 아래 템플릿으로 생성하세요.
결정/인시던트/교훈이 없으면 "해당 없음"으로 최소 기록합니다.

```markdown
---
sprint: {N}
title: "{제목}"
date: "{YYYY-MM-DD}"
status: completed
parts: [{backend|frontend|ai|infra 중 건드린 것}]
related_adrs: ["sprint-{N-1}"]
topics: [{키워드 3~6개}]
tldr: "{한 문단. 무엇을 왜 어떻게 했고 결과가 뭔지. 본문을 안 읽어도 검색되게}"
---
# Sprint {N} — {제목}

_날짜: {YYYY-MM-DD}_

## 목표

{1~3문장}

## 결정 사항

### D1. {결정 제목}
{무엇을 왜 그렇게 결정했는지. 기각한 대안이 있으면 적는다}

## 구현

- **{커밋 해시}** — {한 줄}
- ...

**규모(물리적 사실)**: {N}개 파일, +{a}/−{b}

**검증(물리적 사실)**: {빌드 EXIT 코드, 테스트 통과 수, 렌더 리소스 수 등 실측}

## 인시던트

1. **{제목}**: {무엇이 잘못됐고 어떻게 잡았는지. 실패 모드를 한 줄로}

## 이월

- {다음으로 넘기는 것. 없으면 "없음"}

## 교훈

- **{한 문장 원칙}.** {왜 그런지 한두 문장. 다음에 행동으로 옮길 수 있게}
```

> 검증 절의 수치는 추정이 아니라 실측이어야 합니다. 안 돌려봤으면 "미실행"이라고 씁니다.

## 4단계: 슬라이딩 윈도우 갱신

`sprint-window.md` 를 아래 규칙으로 갱신하세요:

1. 기존 `[1] 완료` → **삭제**
2. 기존 `[2] 다음` → 결과를 채워 `[1] 완료` 로 승격 (start_commit 제거)
3. 새 `[2] 다음` → 사용자 입력으로 작성 (start_commit: 미정)
4. frontmatter `status` 는 아직 **바꾸지 않음** (5단계 검증 후)

> Sprint ADR 파일은 영구 보존합니다. 삭제하지 마세요.

### 윈도우 포맷

```markdown
---
name: 스프린트 윈도우
description: 최근 2 스프린트만 유지하는 슬라이딩 윈도우 — 완료 결과 + 다음 계획
type: project
status: active
---

## [1] 완료 — Sprint {N}: {제목}
- **기간**: {시작일} ~ {완료일}
- **상태**: 완료 ✅ | 구현완료(배포전) 📦
- **작업 요약**:
  - {작업-1}: {한 줄}
- **주요 산출물**: {ADR, 신규 API 등 핵심만}
- **이월 항목**: {없으면 "없음"}

## [2] 다음 — Sprint {N+1}: {제목}
- **start_commit**: (미정 — /sprint-open 실행 시 기록)
- **목표**: {1~2문장}
- **계획 작업**:
  - [ ] {작업-1}: {한 줄}
- **파트**: {backend/frontend/ai/infra 중}
```

## 5단계: MEMORY.md 갱신 + 일관성 검증 + 상태 전환

### MEMORY.md 갱신
- 스프린트 표에 완료 행 추가 (**6행 초과 시 오래된 행 삭제**)
- "후속 처리 필요" 점검: 이번에 해결된 항목 제거
- 200줄 이내 유지

### 일관성 검증
1. `sprint-window.md` [1] → 방금 종료한 스프린트와 일치
2. `docs/adr/sprints/sprint-{N}.md` → 존재 + 번호 일치
3. `MEMORY.md` 표 → 최신 행이 방금 종료한 스프린트

불일치 시 수정하세요.

### 상태 전환 (최종)
모든 검증 통과 후 `status` 를 `idle` 로 바꾸세요.

> **핵심**: idle 전환은 반드시 마지막입니다. 그래야 중단돼도 1단계 가드가 복구합니다.
