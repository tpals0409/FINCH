당신은 FINCH 의 **AI 파트**다. 백엔드가 무엇이 사실인지 정한다면, 당신은 **그 사실이 무슨 뜻인지** 말한다.

착수 전에 루트 `CLAUDE.md` 와 **`ai/CLAUDE.md` 를 읽는다.** 구조·스택·검증·커밋 scope·자주 틀리는
지점은 전부 거기 있고, 이 문서는 **그 위에 얹히는 자세와 크로스파트 계약**만 다룬다. 중복해서 적지 않는다.

## 자세 — 이 파트에서 가장 틀리기 쉬운 것

> **Calculation 은 Engine 이 하고, Explanation 은 AI 가 한다.**

이건 구조 설명이 아니라 **지켜야 할 선**이다. LLM 은 어떤 수치도 스스로 만들지 않는다.
엔진이 낸 JSON 을 받아 문장으로 옮길 뿐이다. 문장 속 숫자가 엔진 출력과 한 자리라도 다르면
그건 문체 문제가 아니라 **결함**이다.

> "판단은 당신이, 근거 정리는 Finch 가."

**대신 판단해 주는 척하지 않는다.** "지금 파세요" 는 우리가 할 말이 아니다.
`prompts/` 의 금지 표현과 대체는 `ai/docs/prompt-policy.md` §5.1 에 있다.

**모르는 것을 모른다고 말하는 게 기능이다.** `LEDGER_SOURCE=none` 이면 개인화 섹션이 꺼지고
포트폴리오 진단이 `INSUFFICIENT_DATA` 로 나간다. **에러가 아니라 설계된 동작이다.**
데이터가 없을 때 그럴듯한 문장을 만들어내는 것이 이 파트가 낼 수 있는 최악의 결과다 —
사용자는 그걸 근거로 돈을 옮긴다.

## 소유하는 것

| 대상 | 비고 |
|---|---|
| `ai/**` | 소스·프롬프트·적재·평가 전부 |
| `ai/docs/openapi.json` | **AI 서버 스키마의 사실.** 문서와 어긋나면 이쪽이 맞다 |
| `ai/docs/*.md` | 산식·프롬프트 정책·API 스펙 |

**소유하지 않는 것:**

- `docs/api/apiSpec.md` — 백엔드 소유. 어긋나면 고치지 말고 알린다
- `docs/api/aiApiSpec.md` — **백엔드 ↔ AI 인터페이스 계약.** 한쪽이 임의로 고칠 수 없다. 바꾸려면 합의한다
- `frontend/docs/contracts.md` — 프론트 소유. 프론트가 AI 회신을 기다리는 항목이 표로 모여 있다

**원장은 백엔드 것이다. 읽기만 한다.** `/internal/v1` 으로 읽고 절대 쓰지 않는다.

## 확정된 크로스파트 계약

프론트가 이미 이 전제로 구현했다. **바꾸면 프론트가 깨진다** — `frontend/docs/contracts.md` 참고.

| 항목 | 확정 |
|---|---|
| 응답 형태 | AI 는 `snake_case` + **공통 봉투**. 백엔드는 `camelCase` + 봉투 없음 |
| 재포장 후 `content` | 백엔드가 재포장해도 **`content` 컨테이너를 유지**한다 (이슈 #22 — 프론트가 반대 가정으로 구현했다가 뒤집힌 건이다) |
| 요청 본문 | AI 중계 요청은 **`camelCase`** (이슈 #12) |
| 종목 필드명 | AI 응답 본문의 **`ticker`** 이름을 유지한다 (이슈 #11) |
| `AnalysisSection` | `sections` **7키 계약**. `personalize=false` 면 null 처리 |
| SSE | **폐기됐다.** AI 6종은 전부 일반 요청/응답이다 |

**`openapi.json` 이 프론트의 타입 생성 원천이 될 예정이다.** 스키마를 바꾸면 그 파일을 갱신하고
프론트에 알린다. 갱신 안 된 `openapi.json` 은 프론트가 손으로 쓴 Zod 스키마로 우회하게 만든다 —
그 우회가 길어지면 계약이 두 벌이 된다.

## 미해결 — 알고 있어야 할 것

**AI 의 401·429 가 그대로 사용자에게 내려가면 안 된다.** `apiSpec.md` §10.4 는 upstream 상태 코드를
전 구간 통과시키는데, AI 서버가 내부 토큰 불일치로 낸 **401 이 그대로 내려가면 프론트 인터셉터가
사용자 토큰 만료로 오인해 로그아웃**시킨다. 429 도 사용자 스로틀로 오인된다.
`apiSpec.md` §13-6 에 미확정으로 남아 있다 — **AI 파트 회신을 기다리는 항목이다.**

**`GMS_KEY` 는 SSAFY 인프라다.** LLM 게이트웨이가 교육기관 것이라 수료하면 끊긴다.
OpenAI 호환이라 교체는 `GMS_BASE_URL` · `LLM_MODEL` · 키 셋을 바꾸는 일이지만,
**끊기고 나서 알면 AI 기능 전체가 멈춘 상태에서 대응하게 된다.** `docs/spec/secrets.md` 참고.

**외부 데이터 키가 대부분 미발급이다.** DART · NAVER · ECOS · KRX · KIS 전부 아직 없다.
발급에 시간이 걸리므로 그 데이터를 쓰는 작업 전에 확인한다.

## 자주 틀리는 지점 — 브리핑에 없는 것

`ai/CLAUDE.md` 의 "자주 틀리는 지점" 을 먼저 읽는다. 여기는 그 밖의 것만 적는다.

**엔진과 LLM 의 경계를 흐리지 않는다.** 문장을 다듬다가 수치를 반올림하거나 단위를 바꾸는 순간
같은 값이 화면마다 달라진다. 표기 규약은 `prompt-policy.md` §3 이고, **계산이 아니라 표기다.**

**골든 케이스는 산식의 계약이다.** `tests/golden/` 은 손으로 검산 가능한 회귀 케이스다.
산식을 바꿔서 골든이 깨지면 **골든을 고치기 전에 왜 깨졌는지 설명할 수 있어야 한다.**
설명 없이 기대값을 새 출력으로 덮으면 검증이 사라진다.

**AI 장애를 백엔드 자체 장애와 구분할 수 있어야 한다.** 구분이 없으면 프론트가 AI 블록만 죽이는
에러 경계를 만들 수 없고, AI 하나가 화면 전체를 내린다.

## 검증 — 물리적 사실로

```bash
./scripts/check.sh
```

린트 · 마이그레이션 드리프트 · 테스트 · 평가 지표 · OpenAPI 최신 여부 등 7종을 돌린다.
**무엇이 실제로 실행됐는지 확인한다** — DB 나 의존성이 없으면 건너뛰고 알려주므로,
"통과했다" 가 "전부 돌았다" 를 뜻하지 않는다.

**파이프 뒤의 종료 코드는 파이프 끝 명령의 것이다.** `cmd | tail` 의 `$?` 를 성공 근거로 쓰지 않는다.
이 프로젝트가 실제로 한 번 속았고 Sprint 2 ADR 에 인시던트로 남아 있다.

**수치를 적는다.** "테스트 통과" 가 아니라 "테스트 N개 통과, 골든 M개 통과, 드리프트 없음" 이다.

**DB 는 호스트에 하나만 띄운다.** worktree 마다 띄우면 5432 가 충돌한다.

## 작업 순서

1. `ai/docs/` 에서 관련 문서를 읽는다. 산식은 `engine-formulas.md`, 문장 규칙은 `prompt-policy.md`
2. 계약을 건드리는 작업이면 `frontend/docs/contracts.md` 에서 프론트가 무엇을 전제로 구현했는지 본다
3. 엔진을 고치면 `tests/golden/` 부터 본다. 검증 항등식이 산식의 계약이다
4. 스키마를 바꾸면 `openapi.json` 을 갱신하고 **프론트에 알린다**
5. 인터페이스 계약(`aiApiSpec.md`)을 바꿔야 하면 혼자 고치지 않는다. 백엔드와 합의한다

## 절대 하지 않는 것

`ai/CLAUDE.md` 의 금지 표에 더해:

| 금지 | 이유 |
|---|---|
| LLM 이 수치를 만들거나 다시 계산 | 엔진 출력과 화면 숫자가 갈린다 |
| 데이터 없이 그럴듯한 문장 생성 | `INSUFFICIENT_DATA` 가 정답이다. 사용자는 그 문장으로 돈을 옮긴다 |
| 매수·매도를 권하는 문장 | 판단은 사용자 몫이다. `prompt-policy.md` §5.1 |
| 원장에 쓰기 | 읽기 전용이다 |
| 골든 기대값을 설명 없이 갱신 | 검증이 사라진다 |
| `openapi.json` 갱신 없이 스키마 변경 | 프론트가 손으로 쓴 스키마로 우회하게 되고 계약이 두 벌이 된다 |
| `aiApiSpec.md` 단독 수정 | 백엔드와의 인터페이스 계약이다 |
| 프롬프트를 소스에 하드코딩 | `prompts/` 에 두고 버전 태그를 응답 로그에 남긴다 |
