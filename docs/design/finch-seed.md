# FINCH SEED

앱의 디자인 토큰 체계다. 당근 SEED 를 옮긴 것이고 원본 방법론은
`~/Desktop/발표자료/계획/Design.md`, 값의 출처는 발표자료(FINCH-presentation)의
`styles/tokens.css` 다.

**이 문서에 값을 적지 않는다.** 값은 `frontend/src/styles/tokens.css` 에만 있다.
여기 적는 것은 구조와 규칙, 그리고 템플릿에서 벗어난 자리의 이유다.

원본 템플릿은 869줄이다. 그걸 통째로 옮기면 아무도 안 읽고, 우리가 지키지 않는 항목이
문서 안에서 거짓말로 남는다. 그래서 실제로 만든 것만 적는다.

---

## 1. 두 파일, 두 층

```
frontend/src/styles/
├─ tokens.css   :root — SEED 토큰 (--finch-*). palette → 역할 → 타이포·반경·모션·깊이
└─ index.css    @import · @font-face · @theme static 별칭 층 · reset/body
```

`main.tsx` 는 `index.css` 하나만 import 하고, `index.css` 가 `tokens.css` 를 `@import` 한다.

| 층 | 사는 곳 | 하는 일 |
|---|---|---|
| **Palette** | `tokens.css` | 사다리. 값을 직접 적는 유일한 곳 |
| **역할** | `tokens.css` | 팔레트 별칭. `fg` / `bg` / `stroke` × role × variant × state |
| **별칭** | `index.css` `@theme static` | 역할 토큰 중 유틸리티로 열 것만 Tailwind 네임스페이스로 옮겨 적기 |

이름은 `--finch-{type}-{category}-{name}` (Design.md §2). 색 역할 토큰은
Property(fg/bg/stroke) · Role · Variant(solid/weak/subtle/contrast/inverted/alpha) · State(-pressed/-selected).

### 별칭 층의 규칙

**팔레트는 절대 별칭에 올리지 않는다.** 올리면 Tailwind 가 `text-palette-gray-700`
유틸리티를 만들고, 존재하는 유틸리티는 언젠가 쓰인다. 그러면 "토큰 밖 색을 쓰지 않는다"는
규칙이 우리 팔레트 안에서 되살아난다.

**역할 토큰도 전부 올리지 않는다.** 별칭 층은 의도적으로 좁은 문이다. 지금 컴포넌트가
실제로 쓰는 것만 손으로 적혀 있고, `tokens.css` 에는 있지만 별칭에 없는 토큰이 더 많다
(pressed · selected · overlay · critical · vivid · up/down 면 · contrast 획).
필요해질 때 한 줄씩 연다.

**별칭 이름은 SEED 역할 이름 그대로다.** `--finch-color-fg-neutral` → `--color-fg-neutral`.
property 세그먼트를 남기는 이유는 Tailwind 의 `--color-*` 네임스페이스가 `bg-` · `text-` ·
`border-` 세 유틸리티에 동시에 열려 있어서다. 이름이 property 를 말해야
"fg 를 배경에 쓰지 않는다"(Design.md §4.6)가 눈으로도 grep 으로도 잡힌다.
대가로 `bg-bg-layer-default` 처럼 겹쳐 읽힌다. 겹침이 싫어서 `bg-` 를 떼면
`bg-neutral`(=잉크)이 배경으로 읽히는 함정이 생긴다. 겹침 쪽을 택했다.

**`@theme static` 의 `static` 을 떼지 않는다.** Tailwind v4 는 유틸리티가 쓰지 않는
테마 변수를 빌드에서 지운다. 그러면 아직 아무도 안 쓴 토큰을 손으로 쓴 CSS 에서
`var()` 로 참조했을 때 조용히 비어 나온다.

**손으로 쓴 CSS 는 별칭이 아니라 `--finch-*` 원본을 읽는다.** `index.css` 의 `body`,
`:focus-visible` 규칙이 그 예다. 별칭은 유틸리티를 위한 것이다.

### 새 토큰이 필요할 때

```
1. 기존 역할 토큰으로 되는가        → 되면 끝. 새 토큰은 마지막 수단이다
2. 안 되면 tokens.css 의 역할 층을 연다 (팔레트 사다리에서 단계를 고른다)
3. 사다리에 없는 단계가 필요하면 ladder.cjs 로 다시 뽑는다. 손으로 보간하지 않는다
4. 유틸리티로 써야 하면 그때 index.css 별칭 층에 한 줄 연다
5. npm run design:contrast 로 검증한다
```

## 2. 의도적 이탈

Design.md §0.1 이 🔒유지로 표시했는데 FINCH 가 벗어난 것이다. 따르지 않기로 한 것이지
아직 못 한 것이 아니다.

| 항목 | 템플릿 | FINCH | 왜 |
|---|---|---|---|
| 서체 | 시스템 폰트 (웹폰트 로드 안 함) | Gmarket Sans 서브셋 woff2 3굵기 | 발표자료와 같은 얼굴이어야 한다. 원본 TTF 2.3MB/굵기 대신 완성형 2350자 서브셋(합계 324K)만 서빙해 비용을 갚았다 |
| 모드 | light/dark 필수, 팔레트·역할 재선언 | **단일 모드** | 발표자료도 단일 모드다. 어두운 화면은 모드 전환이 아니라 어두운 배경 섹션이다. 모드를 하나 더 만들면 검증할 대비 쌍이 두 배가 되고 그 절반은 아무도 안 본다 |
| 단위 | rem + OS 글자 배율 `clamp(0.8~1.5)` | **px** | 기준 뷰포트 390 고정이다. 배율을 받으면 종목 리스트의 행 높이와 숫자 자리폭이 같이 흔들린다 |
| 타입 스케일 | `t1`~`t14` 숫자 14단 | **의미 이름 8단** (`display`…`caption`) | 숫자로 바꾸면 어느 단이 캡션이고 어느 단이 제목인지가 이름에서 사라진다. 화면을 읽을 때마다 표를 봐야 한다 |
| dimension | `x0_5`~`x30` 토큰 23개 | **Tailwind 기본 4px 스케일** | 발표자료의 4px 그리드와 1:1 로 맞는다. 따로 만들면 `p-5` 와 `space-5` 가 같은 값으로 둘 다 존재한다 |
| radius | `r0_5`~`r6` 사다리 | **컴포넌트 이름 5개** | 앱이 쓰는 반경은 다섯 개뿐이고, 각각 어느 컴포넌트의 것인지가 이름에 남아야 고를 때 헷갈리지 않는다 |
| 대비 기준 | WCAG 비율 (4.5 / 3.0) | **APCA Lc** | 비율은 밝은 회색끼리의 차이를 과대평가한다. 무채색 사다리에서 어느 단계가 실제로 읽히는지 판정하려면 Lc 가 맞다. Design.md §14 도 APCA 다 |
| z-index | 전역 스케일 두지 말 것 (§12) | **4단 토큰** | 그 규칙은 포털 DOM 순서를 통제할 수 있는 컴포넌트 라이브러리 얘기다. 앱은 상단 내비·하단 탭바·하단 고정 CTA·FAB·바텀시트가 서로 다른 트리에서 자란다 |
| 도메인 색 | manner-temp, banner, magic 그라디언트 | **전부 삭제** | 당근 전용이다 (§4.5 가 삭제 가능으로 표시) |

## 3. 만들지 않은 역할

다음 사람이 "왜 없지" 하고 다시 만들지 않도록 적는다. **되살리려면 이유부터 반박한다.**

| 없는 것 | 왜 |
|---|---|
| `brand-*` 전체 | 브랜드 색이 없다. Finch 의 브랜드는 잉크의 무게다. 주요 버튼은 `bg-neutral-solid`(잉크 채움) + `fg-neutral-inverted` 다. brand 를 만들면 값이 neutral 과 똑같은 토큰이 한 벌 더 생긴다 |
| `positive-*` · `warning-*` · `informative-*` | 모노톤에서 이 셋의 값은 전부 잉크다. 성공·주의·정보는 색이 아니라 문구와 아이콘과 형태로 구분한다 |
| `fg-*-contrast` 짝 | SEED 는 `-weak` 면 위 글자를 `-contrast` 로 쓰지만, 모노톤에서는 paper 위든 weak 면 위든 같은 잉크다. 값이 같은 토큰을 둘 두는 건 의식(儀式)이다 |
| `bg-critical-solid` | 파괴적 확인 버튼의 채움도 주요 버튼과 같은 잉크다. 구분은 문구와 `bg-critical-weak` 면이 한다 |
| `bg-layer-floating` | 단일 모드라 floating(시트·모달)과 default(카드)가 영원히 같은 값이다. 다크 모드였다면 고도가 높을수록 밝아져서 달랐다. 떠 있다는 건 색이 아니라 `shadow-float` 와 `z-overlay` 가 말한다 |
| `bg-neutral-weak` (불투명 회색 면) | gray-200 은 paper 위에서 Lc 0 이다. 카드 위 회색 칩·선택 면은 전부 알파(`bg-transparent-selected`)로 간다. 알파라야 흰 카드에서도 paper 에서도 아래 면을 같은 양만큼 눌러 살아남는다 |
| `stroke-up-*` · `stroke-down-*` | 캔들 차트는 `bg-up-solid`(몸통)와 `fg-up`(심지·테두리)으로 충분하다. 칩은 안의 글자가 방향을 말한다 |
| white-alpha 사다리 | 반전 표면(토스트·night)이 앱에 없다. 생기면 발표자료에서 가져온다 |
| `--color-primary` | 없어졌다. 옛 파랑 `#3b82f6` 은 하락 숫자와 구분되지 않았다. 프라이머리가 사라지면서 그 충돌도 사라졌다 |
| AI 표면 색 (`--color-ai-surface`) | 모노톤에 "AI 색" 은 없다. AI 박스는 `bg-layer-default` + `stroke-neutral-weak` + `shadow-ai` + `radius-ai` 로, 일반 카드와 획 무게·깊이·반경 셋이 한꺼번에 달라진다. 근거가 확정되지 않은 카드는 테두리를 dashed 로 바꾸고 그림자를 뺀다 — 그건 토큰이 아니라 형태다 |
| `-hover` 상태 | 호버는 `-pressed` 토큰을 빌려 쓴다. 모노톤에 이 용도로 쓸 알파 단계가 사실상 하나뿐이라(alpha-200 은 `selected` 가 이미 쓴다) `-hover` 를 만들면 값이 `-pressed` 와 똑같은 토큰이 한 벌 더 생긴다. §8.3 |
| 포커스 링 두께·오프셋 토큰 | 소비처가 `index.css` 의 전역 규칙 하나뿐이다. `outline` 대신 `box-shadow` 로 링을 그려야 하는 컴포넌트가 나오면 그때 두 곳이 기하를 공유하므로 값을 갖는다. §8.4 |
| `--finch-duration-skeleton` | `animate-pulse` 의 2초는 Tailwind 기본값이고 인정한 예외다. 모션 셋은 마이크로 인터랙션 사다리라서 2초 앰비언트 루프를 넣으면 성질이 다른 값이 하나 섞인다. §8.1 |
| dark 블록 | 위 §2 |

## 4. 색 사용 규칙

- 글자·아이콘은 `fg`, 면은 `bg`, 선은 `stroke`. **`fg` 를 배경에 쓰지 않는다.**
- 눌림 색을 새로 만들지 않는다. `-pressed` 짝을 쓴다. 눌림은 **면 색만** 바뀐다 — 전경에 pressed 가 없다.
- 화면 전체 배경은 `bg-layer-basement`(paper), 그 위 콘텐츠 블록은 `bg-layer-default`.
- **색만으로 의미를 전달하지 않는다.** 등락에는 부호와 화살표, 에러에는 아이콘과 문구가 같이 온다.
  색맹 사용자와 흑백 인쇄 때문만이 아니다 — 아래 두 경우는 색이 물리적으로 안 보인다.
  - **선택·눌림 면**은 APCA 바닥 아래다(Lc 0). 의도한 것이다. 선택은 면 하나로 알리지 않고
    글자 무게나 테두리(`stroke-neutral-contrast`)가 같이 움직인다.
  - **up/down `-weak` 면**은 밝기가 흰 면과 거의 같고 색상(hue)으로만 구분된다.
    면 위 글자(`fg-up` / `fg-down`)가 방향을 말해야 한다.
- **등락은 상승 적색, 하락 청색.** 국내 관례이고 미국식과 반대다.
- **등락은 두 단계다.** 본문·캡션·표 안의 숫자는 `fg-up` / `fg-down`(700단계),
  18px 이상 굵게 나오는 큰 가격만 `-vivid`(600단계). 한 값으로 합치면 13px 캡션에서 반드시 깨진다.
- **에러에 등락 적색을 재사용하지 않는다.** 같으면 "떨어졌다" 로 오독된다.
  폼 에러는 셋을 함께 바꾼다 — 입력 테두리 `stroke-critical-solid`, 메시지 `fg-critical` + bold, 아이콘.
- **비활성은 `opacity` 가 아니라 전용 색.** opacity 는 겹친 자식 아이콘·스피너까지 흐려져 사라진다.
- **숫자는 `tabular-nums`.** `index.css` 가 `body` 전체에 건다. 숫자 글리프에만 붙는
  OpenType 기능이라 문자에는 영향이 없고, 그래서 셀렉터를 좁히지 않고 전역으로 걸었다 (§6).

## 5. 도구

### 사다리 다시 뽑기

`frontend/tools/ladder.cjs`. 지정 단계 사이를 oklab 으로 보간한다. **손으로 보간하지 않는다.**
gray 는 200 paper · 400 외곽선 · 700 캡션 · 900 반전 표면 · 1000 ink 가 지정값이고 나머지가 보간이다.
up·down 은 600 이 원색, 700 이 본문용이며 이 두 단계 분리가 대비 문제를 푼다.

### 대비 검사

```bash
cd frontend && npm run design:contrast
```

`tools/check-contrast.cjs` 가 `tokens.css` 를 읽어 `var()` 체인을 hex 까지 풀고 APCA Lc 를 계산한다.
의존성 0, 순수 node. 기준선은 파일 머리말에 있다 — Lc 90 본문 · 75 일반 · 60 큰 글자·bold ·
45 display · 30 placeholder·비활성 · 15 경계선.

배경 슬롯에 알파 색이 들어오면 던진다. 알파를 아래 면 없이 합성할 수 없는데
그냥 두면 순수 검정으로 읽혀 조용히 틀린 숫자가 나온다.

**검사 표에서 뺀 쌍과 이유** (도구 주석에도 있다):

| 뺀 쌍 | 왜 |
|---|---|
| selected · pressed 면 | 아래 면과의 밝기 차가 APCA 바닥 아래다. 숫자로 지키는 규칙이 아니라 형태로 지키는 규칙이다 (§4) |
| up/down `-weak` 면 자체 | hue 로만 구분된다. APCA 는 밝기만 본다. 면 위 글자로 대신 검사한다 |
| 잉크 면 위 focus-ring | 링은 `outline-offset` 으로 요소 바깥(paper 또는 카드)에 떠 있어야 하고, 그 쌍은 표에 있다 |
| night 섹션 계열 | 앱에 반전 표면이 없다. 발표자료 전용이다 |

### 팔레트 유출 검사

```bash
grep -rnE '(bg|text|border)-(red|blue|gray|slate|zinc)-[0-9]|\[#[0-9a-fA-F]{3,6}\]' frontend/src --include='*.tsx' | grep -v styles/
grep -rn 'palette-' frontend/src --include='*.tsx'
```

첫째는 Tailwind 기본 팔레트와 하드코딩 hex, 둘째는 우리 팔레트 층 직접 참조를 잡는다.
둘 다 비어야 한다. 지금 유일한 예외는 `Button.tsx` 의 카카오 로그인 버튼(`bg-[#FEE500]
text-[#191600]`)이다 — 카카오 브랜드 가이드가 강제하는 색이라 토큰화하지 않는다.

## 6. 결정 기록

값이 아니라 판단이 들어간 자리다. 되짚을 근거가 필요할 때 본다.

**포커스 링이 잉크인 이유.** 발표자료는 down-600(파랑)을 쓴다. 증권 화면에서 파란 링은
"하락"과 섞이고, 모노톤에 유채색을 하나 더 들이는 셈이다. 그래서 `stroke-focus-ring` 은 잉크다.
대신 **반드시 `outline-offset` 으로 요소 바깥에 띄운다** — offset 0 이면 잉크 채움 버튼 위에서
링과 버튼이 같은 색이라 사라진다. `index.css` 의 `:focus-visible` 규칙이 2px 링 + 2px offset 을
전역으로 건다. 반전 표면이 생기면 반전용 링 토큰이 그때 필요하다.
**그 규칙을 캐스케이드 레이어 밖에 두는 것도 결정이다 — §8.4.**

**elevation 이 4단인 이유.** base 0 · sticky · floating · overlay. 10 씩 띄운 건 일회성 예외가
사이에 들어와도 전체를 다시 매기지 않기 위해서다. 딤·시트·다이얼로그·토스트는 모두 overlay 한 층이고
그 안의 순서는 포털 DOM 순서로 정한다. 토스트가 다이얼로그 위에 와야 하는 것도 DOM 순서에 달려 있다.

**z 토큰에 쓸 길을 낸 이유.** `--finch-z-*` 넷은 있었지만 Tailwind v4 에 `z` 테마
네임스페이스가 없어 유틸리티가 생기지 않았다 — `z-sticky` 같은 클래스는 애초에 만들어지지
않는다. `duration` 이 이미 같은 문제였고 `index.css` 가 `:root` 에 `--motion-*` 별칭을 두고
`duration-(--motion-fast)` 임의값 문법으로 풀었다. z 도 같은 자리에 `--z-*` 로 별칭을 냈다 —
`z-(--z-sticky)`. `@theme` 이 아니라 `:root` 인 이유도 같다: 테마 네임스페이스가 없는 값은
`@theme` 에 넣어도 유틸리티가 안 생긴다.

**이 결정에 함정이 하나 딸려 있고 실제로 밟혔다.** `z-overlay`·`z-sticky` 라고 적으면
CSS 가 한 줄도 안 나오는데(프론트 실측: `.z-overlay{` 규칙 0건) 클래스 이름이 그럴듯해서
리뷰를 통과한다. `z-(--z-overlay)` 만 컴파일된다. 지금 그 결과로 FAB 이 바텀시트 위에 뜬다 —
자세한 건 §8.6.

**숫자 `tabular-nums` 를 `body` 전체로 넓힌 이유.** 원래 `:where(table, dd, output, time)`
넷에만 걸려 있었는데, 종목 시세 행처럼 리스트 안 `<span>` 으로 그려지는 숫자는 그 넷 중
어디에도 안 든다. `font-variant-numeric` 은 숫자 글리프에만 붙는 OpenType 기능이라 문자
렌더링에는 영향이 없다 — 그래서 셀렉터를 하나씩 추가하는 대신 `body` 에 걸어 모든 숫자를
한 번에 덮었다. 새 컴포넌트가 이 규칙을 챙기려고 클래스를 기억할 필요가 없다.

**비활성 두 단계를 함께 내린 이유.** 측정이 근거다.

| 면 / 글자 | 면 vs paper | 라벨 vs 면 |
|---|---|---|
| 발표자료 (gray-200 / gray-500) | 0.0 | 39.8 |
| 중간안 (gray-300 / gray-500) | 10.6 | 26.8 |
| **채택 (gray-400 / gray-600)** | **22.8** | **30.0** |

발표자료의 비활성 면은 흰 슬라이드 카드 위에만 놓인다. 앱의 하단 고정 CTA 는 paper 위에도 놓여서
그대로 쓰면 버튼 모양이 배경에 녹는다. 버튼 모양이 안 보이는 게 라벨이 흐린 것보다 나쁘다고 봤다.
라벨 30.0 은 비활성 기준선을 0.05 차로 넘는다 — **사다리를 다시 뽑으면 이 쌍부터 확인한다.**

**`shadow-float` 를 s3 으로 옮긴 이유.** 처음 값은 s1~s3 사다리 밖이었다. 한 값이라도
사다리를 벗어나면 사다리가 출처 구실을 못 한다.

**`stroke-neutral-subtle` 이 알파가 아닌 이유.** 발표자료는 black-alpha-200 을 쓰지만
흰 카드 위에서 Lc 0 이라 카드 안 구분선이 통째로 사라진다. 발표자료의 구분선은 paper 위에만
놓여서 문제가 안 됐다. 앱은 불투명 gray-300 을 쓴다.

**흰 카드는 paper 위에서 Lc 0 이다.** 면 색만으로는 카드 경계가 안 보인다.
경계는 `stroke` 가 만든다 — **카드에서 테두리를 빼지 않는다.**

## 8. 모션과 상태

토큰 값은 `tokens.css` §9 다. 여기 적는 것은 **어디에 무엇을 쓰는가**와,
호버·포커스·눌림·선택이라는 상태 어휘다.

`frontend/docs/frontConvention.md` 는 프론트 소유다. 같은 결정을 그쪽이
구현 규칙으로 다시 적는다 — **어긋나면 이 문서가 어휘의 기준이고 그쪽이 구현의 기준이다.**

### 8.1 애니메이션을 거는 자리

세 단계뿐이고 이징은 `ease-standard` 하나다. 새 단계를 만들기 전에 이 표에서 고른다.

| 대상 | 토큰 | 무엇이 움직이나 |
|---|---|---|
| 버튼·행·칩 눌림 | `fast` | 면 색만. 크기·위치는 안 움직인다 |
| 데스크톱 호버 | `fast` | 면 색만 (§8.3) |
| 칩·세그먼트 선택 | `fast` | 면 색 + 테두리 색 |
| 탭 인디케이터 | `fast` | 밑줄의 `translateX` (§8.7) |
| 아코디언 · 근거 목록 접기 | `normal` | 높이 |
| 바텀시트 열림 | `sheet` | 시트 `translateY` + 딤 `opacity` 동시 |
| 에러·토스트 등장 | `normal` | **`opacity` 만.** slide 를 쓰지 않는다 — 제출 버튼 근처에서 움직이는 표적은 오탭을 부른다 |

**`transition-colors` 를 쓰지 않는다. `transition-[background-color,border-color]` 로 좁힌다.**
프론트가 빌드 CSS 에서 잰 `.transition-colors` 의 property 목록에 **`color` 와 `outline-color` 가
들어 있다.** 그래서 이 유틸리티 하나가 §8.2 의 금지 둘을 동시에 새게 한다.

- **`outline-color`** → 포커스 링이 140ms 페이드인한다. `Button.tsx` 가 이미 그렇게 돼 있어서
  "포커스 링 등장에 트랜지션 없음" 이 master 에서 이미 깨져 있었다
- **`color`** → 시세를 품은 요소를 `LinkButton` 으로 만드는 순간(종목 행 → 상세) 그 요소 자신의
  `fg-up` ↔ `fg-down` 이 보간되고 **중간에 회색을 지난다.** §8.2 가 "절대 금지" 라고 쓴 그것이다.
  (`transition-property` 는 상속되지 않으니 행 **안**의 자식 `<span>` 은 안전하다. 위험한 건
  색을 자기 자신에 갖는 요소다)

좁히면 이 둘이 **구조적으로 불가능해지고 `grep -rn 'transition-colors' src` 로 강제된다.**
눌림·호버·선택이 실제로 바꾸는 건 면과 테두리뿐이라 잃는 것이 없다.

**바텀시트는 열림 `sheet` · 닫힘 0 이다.** 주문·충전은 화면 표현만 시트고 실제로는
**라우트**다(`ia.md` §3). React Router 는 이동하는 순간 나가는 트리를 언마운트해서 exit 를 걸
자리가 없다. 나가는 트리를 React 로 붙잡는 방법은 URL 과 렌더 트리가 어긋나는 값을 치른다.
**뒤로가기로 닫는 시트는 URL 이 이미 "나갔다" 고 말하는데 화면이 260ms 더 남아 있는 쪽이
원래 어색하다** — 그래서 닫힘 0 을 결함이 아니라 어휘로 확정한다.

`react-router-dom` 이 `startViewTransition` 을 이미 싣고 있어서(프론트 실측) 브라우저가
나가는 DOM 의 스냅샷을 잡아 주는 길이 있다. **그건 "공짜로 얻으면 좋은 것" 으로 두고 어휘로
삼지 않는다** — 미지원 브라우저의 폴백이 정확히 닫힘 0 이라, 0 으로 정해 두면 어휘가 어느
브라우저에서도 거짓말을 하지 않는다. 쓰기로 하면 §8.5 의 구멍을 먼저 막는다.

**이징을 쪼개는 조건.** `ease-standard` 는 ease-out 이라 엄밀히는 들어오는 쪽 곡선이다.
`sheet` 길이에서는 나가는 데 써도 티가 안 난다고 봤다. 시트가 두 종류(위에서 내려오는 것 +
아래서 올라오는 것)가 되면 그때 exit 곡선을 만든다.

**`animate-pulse` 는 인정한 예외다.** Tailwind 기본값 2초로 세 단계 밖이다. 그대로 쓴다 —
세 단계는 마이크로 인터랙션 사다리고 2초 주기 앰비언트 루프는 성질이 다르다. 여기에
`--finch-duration-skeleton` 을 만들면 사다리에 종류가 다른 값이 하나 섞인다.

### 8.2 애니메이션을 걸지 **않는** 자리

이쪽이 더 중요하다. 증권 화면에서 잘못 움직이는 것은 안 움직이는 것보다 나쁘다.

| 대상 | 왜 |
|---|---|
| **갱신되는 숫자** — 잔고·시세·평가금액·손익 | 트랜지션도 count-up 도 없다. 돈이 흐르는 것처럼 보이면 값이 확정된 것으로 안 읽힌다. `tabular-nums` 가 폭을 잡고 있으니 값만 바뀐다 (§4) |
| **등락 색 뒤집힘** — 상승 적 ↔ 하락 청 | **절대 금지.** 빨강→파랑을 보간하면 중간에 회색을 지난다. 그 순간 숫자가 "보합"(`fg-flat`)으로 읽힌다 |
| **스켈레톤 → 값** | 페이드조차 걸지 않는다. 스켈레톤이 이미 자리를 잡아 레이아웃이 안 흔들리므로, 페이드는 사용자가 기다린 숫자를 그만큼 더 못 읽게 만드는 것뿐이다 |
| **무한 스크롤로 붙는 행** | 등장 애니메이션 없음. 스크롤 관성과 싸우고 긴 목록에서 jank 가 된다. 하단 로딩 표시는 `Skeleton` 행 하나다 |
| **차트 기간 변경** — 1M↔3M↔1Y | morph·tween 없음. x 도메인이 통째로 다른 데이터라 보간에 의미가 없다. 단 **처음 보는 기간은 스켈레톤, 다시 보는 기간은 즉시** — "즉시 재그리기" 는 데이터가 이미 있다고 가정하고, 각 기간의 첫 요청에는 없다(두 번째부터는 TanStack 캐시가 즉시로 만든다) |
| **탭 패널 내용** | 전환 없음. 탭은 URL 검색 파라미터(`ia.md` §2)라 바뀌면 쿼리 경계가 다시 도는 경우가 많다 — 스켈레톤으로 페이드인하는 건 아무것도 안 하는 것보다 나쁘다 |
| **탭바 화면 간 라우트 전환** | 페이지 트랜지션 없음. 애니메이션하려면 나가는 트리를 붙잡아야 하고 `Suspense` 폴백과 겹친다 |
| **포커스 링 등장** | 트랜지션 없음. 키보드 이동에 늦게 따라오는 링은 고장으로 느껴진다 |
| **FAB 등장** | scale-in 없음. 라우트가 맞으면 나타나는 요소라 이동마다 튀면 노이즈다. 눌림 피드백만 |
| **비활성 전환** | 트랜지션 없음. `disabled` 는 상태가 아니라 사실이다. 흐려지는 중인 버튼은 아직 누를 수 있는 것처럼 보인다 |

### 8.3 호버 — `-hover` 상태를 만들지 않는다

주 대상은 390px 터치 기기지만 데스크톱 브라우저에서도 열린다. 호버가 아예 없으면
커서 모양 말고 아무 반응이 없어서 누를 수 있는 줄 모른다. 그래서 만들되, **역할을 새로 만들지 않는다.**

**호버는 `-pressed` 토큰을 빌려 쓴다.** 잉크 버튼은 `bg-neutral-solid-pressed`,
칩·금액 프리셋·결제수단·필터 탭은 `bg-transparent-pressed`. `active:` 도 같은 값이다.
**목록 행은 아직 아니다** — `TransactionRow` 는 `<li>` 로 클릭 대상이 아니다(프론트 실측).
행이 탭 가능해지면 새 토큰을 만들지 말고 같은 `transparent-pressed` 를 쓴다.
근거는 §3 이 `brand-*` 와 `fg-*-contrast` 를 안 만든 것과 같다 — 모노톤에 이 용도로 쓸
알파 단계가 사실상 하나뿐이라(alpha-200 은 `selected` 가 이미 쓴다) `-hover` 를 만들면
값이 `-pressed` 와 똑같은 토큰이 한 벌 더 생긴다.
**대가:** 데스크톱에서 호버와 눌림이 같아 보인다. 마우스는 클릭이 즉발이고 커서가 이미
표적을 말하므로 받아들일 만하다고 봤다.

- **호버는 면 색만 바꾼다.** `translateY`·`scale`·`box-shadow` 승격을 쓰지 않는다.
  목록 행이 떠오르면 시세 정렬이 흔들려 보인다.
- **붙이는 대상은 셋뿐이다.** 버튼, 탭 가능한 목록 행, 칩·세그먼트.
  카드 자체·AI 박스·텍스트에는 안 붙인다.
- **각주에 호버 툴팁을 만들지 않는다.** `ia.md` §4 가 이미 그렇게 정했다 — 모바일에 호버가 없다.

**터치에서 호버가 탭 후 남는 문제는 우리가 할 일이 없다.** Tailwind v4.3.3 이 `hover:` 를
`@media (hover: hover)` 로 감싸서 컴파일한다 — 프론트가 빌드된 CSS 에서 확인했고, hover
유틸리티 전부가 파일 전체에 하나뿐인 그 블록 안에 모인다. 터치 기기에서 미디어 쿼리가 매치되지
않으므로 **sticky hover 가 물리적으로 발생하지 않는다.** 커스텀 variant 를 만들지 않는다.
`active:` 와 `focus-visible:` 은 미디어 가드 없이 평범한 셀렉터로 나온다 — 의도한 대로다.

### 8.4 포커스

**기하는 이미 정해져 있고 한 곳에만 있다.** `index.css` 의 전역 `:focus-visible` 규칙이
2px 잉크 링 + 2px 오프셋을 건다. 색이 잉크인 이유와 오프셋이 필수인 이유는 §6 이다.

**그 규칙을 캐스케이드 레이어 밖에 두는 것은 결정이다.** 레이어 없는 규칙은 명시도와
무관하게 `@layer utilities` 안의 규칙을 이긴다. 그래서 **어떤 Tailwind 유틸리티도 링을
끌 수 없다** — 누가 `focus:outline-none` 을 적어도 링은 살아 있다(프론트가 computed 값으로
실측: `outline: rgb(18,20,23) solid 2px`). 규율로 지키던 규칙을 플랫폼이 강제하는 쪽으로
바꿔 주는 셈이라 그대로 둔다. **`@layer base` 로 옮기지 않는다** — 옮기면 유틸리티가 이길 수
있게 되고, 그 순간 `focus:outline-none` 같은 사고가 실제로 링을 죽인다.

**잠긴 것은 `outline` 하나뿐이다.** `focus-visible:bg-*` · `focus-visible:border-*` ·
`focus-visible:ring-*`(box-shadow)는 다른 프로퍼티라 그대로 이긴다. 컴포넌트는 포커스
표현을 **더할 수는 있고 뺄 수는 없다.** 이 비대칭이 의도한 것이다.

**예외가 필요하면 경로는 하나다** — `index.css` 의 전역 규칙에 `:where()` 카브아웃을 넣는다.
컴포넌트 작성자가 인라인 클래스로 혼자 정하지 못하는 것이 요점이다.

**두께·오프셋을 토큰으로 만들지 않는다.** 소비처가 그 규칙 하나뿐이라 정의만 되고 쓸 길이
없는 토큰이 된다. **만들 조건**: `overflow: hidden` 에 잘려서 `outline` 대신 `box-shadow` 로
링을 그려야 하는 컴포넌트가 실제로 나오면, 그때 같은 기하를 두 곳이 공유하므로 값을 갖는다.

**`stroke-focus-ring` 을 별칭 층에 열지 않는다.** 열면 컴포넌트마다 손으로 링을 그리기
시작해 전역 규칙과 어긋난다. **링은 전역 규칙 하나가 그린다.**

**컴포넌트별 예외가 필요한 자리를 셋 검토하고 셋 다 기각했다.** 근거는 하나다 — 링은
`outline-offset` 으로 요소 **바깥**에 있어서 요소 자신의 면 위에 얹히지 않는다.

| 예외 후보 | 왜 예외가 아닌가 |
|---|---|
| 잉크 채움 버튼 위 inset 링 | 링은 버튼 밖 paper/카드에 뜬다(Lc 100.3 / 105.1). inset 으로 바꾸면 오히려 잉크 위 잉크가 되어 사라진다 — offset 이 필수인 이유가 이것이다 |
| 카카오 노랑 위 대비 확보 | 링이 노랑 위에 오지 않는다. 같은 이유 |
| 탭바 안쪽 링 | 링이 탭바 상단선을 넘는 건 맞지만, 그건 링을 안으로 넣을 이유가 아니라 탭바에 `overflow-hidden` 을 걸지 않을 이유다(아래 3) |

1. **`focus:outline-none` 금지.** 예외 없다. `focus`(`focus-visible` 아님)를 끄면
   키보드 사용자만 조용히 잃는다. 마우스 사용자는 아무 차이를 못 느껴서 리뷰에서도 안 걸린다.
2. **링을 옮겨야 하면 지우지 말고 옮긴다.** 합성 컨트롤에서 래퍼에 링이 와야 하면 —
   자식에 `focus-visible:outline-none` + 래퍼에 `:has(:focus-visible)` 로 같은 링.
   자식만 끄고 끝내지 않는다.
3. **포커스 가능한 자식을 가진 컨테이너에 `overflow-hidden` 을 걸지 않는다.**
   2px 링 + 2px 오프셋이 잘린다. 불가피하면 컨테이너 안쪽에 4px 이상 여백을 준다.
   `rounded-card overflow-hidden` 조합이 특히 위험하다.
4. **바텀시트가 열려 있으면 배경은 `inert`.** 네이티브 속성 하나가 탭 순서와 접근성
   트리에서 배경을 통째로 빼주므로 포커스 트랩 라이브러리가 필요 없다. 여는 순간 시트 안으로
   포커스를 넣고, 닫을 때 열었던 트리거로 돌려준다.

   **radix `Dialog` 만으로는 안 된다. 이건 실측된 사실이다.** 프론트가 잰 바로는 radix 가
   바깥에 `aria-hidden` 과 `pointer-events: none` 은 걸지만 **탭 순서에서는 빼 주지 않아서
   뒤의 「충전하기」 버튼에 키보드 포커스가 닿았다.** `pointer-events: none` 은 마우스만 막는다.
   `inert` 이 추가로 필요하고, 충전 화면은 이미 그렇게 하고 있다.

   **충전의 `IDEMPOTENCY_IN_PROGRESS` 시트가 이 규칙이 존재하는 이유다** — 배경이 살아
   있으면 키보드로 뒤의 충전 버튼에 닿는다. 진행 중 버튼은 `disabled` 로 두고
   `bg-disabled`/`fg-disabled` 를 쓴다. `opacity` 는 자식 스피너까지 흐려 사라진다 (§4).

### 8.5 `prefers-reduced-motion`

`index.css` 하단의 전역 블록 하나가 트랜지션·애니메이션 시간을 0 에 가깝게 줄인다.
**토큰 값을 `0ms` 로 덮어쓰는 방식은 택하지 않았다** — 토큰을 읽지 않는 것이 샌다.
`animate-pulse` 는 Tailwind 기본값이고, 앞으로 누군가 `duration-200` 을 직접 적을 수도 있다.

시간만 사라지고 **나타남·사라짐 자체는 남는다.** 시트는 여전히 열리고, `Skeleton`(사용처 23곳)은
`opacity: 1` 프레임에 멈춰 정지한 회색 블록으로 남는다. 완전한 0 이 아니라 0.01ms 인 이유는
0 이면 `transitionend`·`animationend` 가 안 와서 그걸 기다리는 코드가 멈추기 때문이다 —
radix 의 `usePresence` 가 정확히 `animationend` 로 언마운트를 판정한다.

**그래서 radix 시트의 exit 는 `transition` 이 아니라 `@keyframes` 로 쓴다.** `usePresence` 는
transition 을 추적하지 않는다. 이건 위 0.01ms 선택이 만든 제약이라 여기 적는다.

**닿지 않는 곳 둘.** 규칙을 못 미치는 자리를 적어 둔다 — 없는 줄 알고 지나가는 게 더 나쁘다.
- **`::view-transition-*` 의사요소.** `*` 셀렉터가 매치하지 못한다. §8.1 의 view transition 을
  쓰기로 하면 이 구멍을 따로 막아야 한다. 그게 그 길을 어휘로 삼지 않은 이유 중 하나다
- **`lightweight-charts` 의 캔버스.** canvas + `requestAnimationFrame` 이라 CSS 가 닿지 않는다.
  §8.2 가 차트에 "즉시 재그리기" 를 정해 둬서 지금은 문제가 아니지만, **reduced-motion 이
  차트를 제어할 수 없다**는 사실은 차트에 애니메이션을 넣으려는 사람이 알아야 한다

### 8.6 반응형 — `fixed` 층은 본문과 같은 열을 쓴다

브레이크포인트·최소 폭·터치 크기·safe-area 는 `frontConvention.md` §8 이 정했고 확정이다.
**다시 정하지 않는다.** 여기 적는 것은 그 규칙이 덮지 못하는 자리 하나다.

**`sm`·`md`·`lg` 에서 달라지는 화면은 없다. 시안은 390 과 320 둘로 끝난다.**
`PageMain` 이 `mx-auto w-full max-w-md` 로 잡는 열은 390 뷰포트에서 콘텐츠 폭 350px,
448px 이상에서 408px 로 고정된다 — 즉 390~448 사이에서만 커지고 그 위로는 영원히 같다.
매매 내역의 긴 목록도 종목 상세 차트도 이 열에 남는다. 표 레이아웃으로 넓히는 것은
데스크톱 전용 레이아웃이고 그건 금지다. **넓은 화면에 남는 여백은 버그가 아니라 결정이다.**

**그런데 `PageMain` 이 잡는 건 문서 흐름 안의 것뿐이다.** `position: fixed` 는 뷰포트
기준이라 바텀시트·하단 고정 CTA·하단 탭바·FAB 가 전부 이 열을 벗어난다. 넓은 화면에서
시트가 뷰포트 폭으로 펼쳐지고 콘텐츠는 가운데 408px 에 갇힌다.

**규칙: 하단에 붙는 모든 `fixed` 층은 `PageMain` 과 같은 열을 쓴다 —
`mx-auto w-full max-w-md`, 그리고 좌우 여백이 필요한 것은 `px-5` 까지.** `px-5` 를 빼면
FAB 이 448px 열의 맨 오른쪽 끝에 붙어 본문 여백과 어긋난다. 딤(`bg-overlay`)만 예외로
전체 뷰포트를 덮는다. 그림자 없는 흰 시트가 뷰포트 폭으로 펼쳐지는 것보다, 열 안에
`shadow-float` 로 떠 있는 편이 맞다. 열 폭 자체는 토큰으로 두지 않는다 — `max-w-md` 한
문자열이 `PageMain` 과 `fixed` 층에서 같이 grep 되면 그것으로 충분하다.
충전의 진행중 시트는 이미 이 열을 쓰고 있다(규칙과 독립적으로 수렴했다).

**`z-overlay` · `z-sticky` 는 컴파일되지 않는 죽은 클래스다.** 프론트 실측: `.z-overlay{`
규칙 **0건**, `.z-sticky{` **0건**. Tailwind 에 `z` 테마 네임스페이스가 없어서
`--z-*` 를 `:root` 에 둔 것이고(§6), 그래서 **`z-(--z-overlay)` 임의값 문법만 컴파일된다.**
`z-overlay` 라고 적으면 CSS 가 한 줄도 안 나오는데 클래스 이름이 그럴듯해서 리뷰를 통과한다.

지금 그 결과가 실제 버그로 나와 있다 — 진행중 시트의 딤과 시트에 **z-index 가 아예 없고**
(포털이 `body` 끝에 붙어 우연히 작동), `AiFloatingOverlay` 의 `z-40` 은 Tailwind 기본
유틸리티라 진짜로 적용된다. **그래서 FAB 이 시트 위에 뜬다.** `--finch-z-floating` 은 20,
`--finch-z-overlay` 는 30 이라 사다리대로면 시트가 위다. `z-overlay`·`z-sticky` 문자열을
전수 grep 해야 한다 — 사다리가 있는데 아무도 그 값을 안 받고 있는 상태다.

### 8.7 탭 인디케이터 — 균등 분할로 측정을 없앤다

**탭은 `flex-1` 균등 분할이다.** 그래야 인디케이터가 `fast` 로 움직일 수 있다.

문제는 서체다. Gmarket Sans 는 `font-display: swap` 이라(§2) **도착하는 순간 탭 라벨 폭이
바뀐다.** 인디케이터 폭이 콘텐츠에서 나오면 그때 밑줄이 혼자 움직여 버그로 보이고, 막으려면
`ResizeObserver` 로 폭을 재야 한다.

균등 분할이면 폭이 콘텐츠가 아니라 백분율에서 나온다 — `width: calc(100% / n)` +
`translateX(calc(var(--i) * 100%))`. **서체가 도착해도 인디케이터는 안 움직인다.** 라벨 자체는
리플로우하지만 그건 서체 교체의 정상 동작이다. 측정이 필요 없으니 `fast` 140 으로 충분하다.

매매 내역의 필터 탭은 밑줄 대신 **칸별 면 색 교체**(`bg-layer-default`)로 이미 만들어져 있고,
그쪽은 인디케이터가 아예 없어서 이 문제를 원천적으로 피한다. 둘 다 맞다 — 규칙은
"인디케이터를 쓰면 균등 분할" 이지 "인디케이터를 써라" 가 아니다.

### 8.8 미결

프론트와 합의하지 못했거나 이 회의 범위를 넘은 것이다. **합의된 것처럼 읽지 않는다.**

| 미결 | 상태 |
|---|---|
| `disabled` 로 넘어갈 때 전이하지 않는 기전 | §8.2 는 "비활성 전환 없음" 이고, `transition-[background-color,border-color]` 로 좁혀도 `disabled:` 의 면 색은 여전히 전이한다. `not-disabled:` 로 되는지는 프론트가 판단한다. 안 되면 §8.2 에서 그 줄을 뺀다 |
| view transition 채택 여부 | §8.1 은 닫힘 0 을 어휘로 확정했다. view transition 을 쓸지는 프론트 결정이고, 쓰면 §8.5 의 `::view-transition-*` 구멍을 먼저 막는다 |
| `z-40` · 죽은 `z-` 클래스를 누가 고치나 | 원인은 `AiFloatingOverlay` 의 컨테이너지 FAB 자체가 아니다(§8.6). 프론트와 fab 작업자 사이에서 정한다 |
| 목록 행의 탭 가능 여부 | 지금 `<li>` 다. 탭 가능해지면 §8.3 의 `transparent-pressed` 를 쓴다 — 새 토큰을 만들지 않는다 |
