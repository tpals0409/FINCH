# Sprint 5 — 화면과 시세

_날짜: 2026-09-04_

## 목표

Sprint 4 가 만든 세 엔드포인트에 화면을 붙이고, **세민이 와이어프레임을 기준으로 직접 QA** 한다.

스코프가 스프린트 중에 두 번 바뀌었다. KIS 앱키가 없어 시세를 뺐다가, 발급됐다는 소식에 다시 넣었고,
결국 네트워크가 막아 못 했다. 그 대신 **서비스 전체 시안**과 **모션·상태 어휘**가 들어왔다.

## 결정 사항

### D1. 아트보드 하나가 화면 하나다 — QA 단위를 프레임으로

처음엔 시안 세 벌을 아트보드 3개로 올렸다. QA 하려면 화면 하나씩 봐야 한다는 요구가 나와 70개로 쪼갰다.

쪼개니 **폰트가 막았다.** 아트보드마다 독립 iframe 이라 Gmarket Sans 3종(329KB)이 70번 들어가 30MB 를
넘는다(한도 16MB). **화면별로 그 화면에 쓰인 글자만 서브셋**해서 풀었다 — 아트보드당 평균 60KB,
전체 **7.6MB**.

그 다음 "아트보드 자체가 핸드폰 화면" 이어야 한다는 요구가 왔다. 프레임이 아트보드 안에서 떠 있었고
원인이 셋이었다 — 시안의 캔버스 여백(`body{padding:44px}`), `x-dc{display:flex}`, 그리고 `.ph` 자신의
테두리·20px 라운드. 셋 다 "회색 시트 위에 놓인 폰" 을 그리려던 것인데 **아트보드가 곧 폰이 되는 순간
이중 프레임**이 된다. 덮어썼다.

**이 셋은 DOM 측정으로는 안 잡혔다.** 390×844 는 맞았고, 그게 아트보드를 채우는지는 다른 질문이었다.
처음으로 눈으로 보고서야 드러났다.

### D2. AI 플로팅 버튼을 홈에도 놓는다 — `ia.md §7` 미확정 해소

QA 에서 "AI 기능에 접근하는 방법이 없다" 가 나왔다. 재 보니 시안 69개 중 FAB 이 그려진 화면이
**둘뿐**이었고, 하단 탭에 AI 가 없어 **AI 채팅은 종목 상세 한 화면을 거치지 않으면 열 수 없었다.**

`ia.md §3` 이 "PRD 는 홈을 뺐고 프로토타입은 넣었다, 어느 쪽인지 미확정" 으로 남겨 둔 항목이다.
**프로토타입 쪽(홈 포함)으로 확정**했다 — 홈이 가장 자주 열리는 화면이고 거기 없으면 발견성이 죽는다.

**모든 상태 변형에 놓는다.** 기본 상태에만 있고 로딩·에러·빈 상태에 빠지는 것이 누락의 패턴이었다.
"없는 종목코드" 화면도 넣었다 — 처음엔 "넘길 맥락이 없으니 빼라" 고 지시했다가 취소했다.
**맥락이 없다는 게 AI 를 못 열 이유는 아니다. 화면이 비어 있을수록 물을 곳이 더 필요하다.**

### D3. 종목 마스터의 원천을 AI `instruments` 1회 복사로

셋 중 둘이 막혀 있었다. **DART** 는 정석 원천이지만 키 미발급, **KRX** 는 마스터 계열이 로그인을
요구, **KIS** 는 앱키가 나왔지만 마스터가 REST 가 아니라 `.mst` 파일이다.

AI 서비스가 DART 로 이미 받아 검증해 둔 2,598행을 **한 번 복사**했다. 런타임 의존이 아니다 —
이 파일이 생긴 뒤로 백엔드는 AI 를 부르지 않는다.

**마이그레이션에 뒀다.** `apiSpec 5.1` 이 "종목 마스터는 프로젝트 기간 중 고정 적재" 라고 못박았고,
앱이 이 행들 없이는 검색·상세·주문 어느 것도 못 하니 개발 편의용 시드가 아니라 레퍼런스 데이터다.
테스트 시간은 10초 → 11초.

`daily_candle` 은 같이 넣지 않았다 — 캔들은 수집으로 쌓이는 값이라 표본 32종을 마이그레이션에 넣으면
그 표본이 운영까지 따라간다.

### D4. `GET /watchlist` 를 만들지 않았다

담기·빼기·`watched` 판정만 만들었다. 목록 응답이 `currentPrice`·`changeAmount`·`changeRate` 를
요구하는데 `price` 도메인이 없다. **0 을 채우면 값이 있는 종목에 0원을 그리는 거짓**이고
`sort=CHANGE_RATE` 는 기준 값 자체가 없어 정렬이 성립하지 않는다.

한도(50개) 검사에 **잠금을 걸지 않았다.** 50·51번째 동시 요청이면 둘 다 통과할 수 있지만 최악이
51개이고 되돌릴 수 없는 손실이 아니다 — 돈이 움직이는 경로가 아니라 잠금 비용을 안 치르는 쪽을 골랐다.
계좌 잔액과 의도적으로 다르게 다뤘다.

### D5. 모션·상태 어휘 — 안 거는 자리를 더 길게 정했다

토큰 3단계(`fast 140` · `normal 200` · `sheet 260`)는 있었는데 쓰는 규칙이 없었다.
`hover:`·`active:`·`focus-visible:` 이 코드베이스에 **0회**였다.

**금지 목록이 허용 목록보다 길다** — 갱신되는 숫자, 등락 색 뒤집힘(보간이 중간에 무채색을 지나
"보합" 으로 읽힌다), 스켈레톤→값, 무한스크롤 추가 행, 라우트 전환, 포커스 링 등장.

**`transition-colors` 를 영구 금지**했다. 그 유틸리티의 property 목록에 `outline-color` 와 `color` 가
들어 있다 (D-인시던트 1).

**호버는 할 일이 0** 이었다 — Tailwind 4.3.3 이 `hover:` 를 `@media (hover:hover)` 로 이미 감싼다.
**반응형도 448px 한 벌**로 끝났다. 대신 규칙이 못 덮던 자리를 찾았다 — `fixed` 층(시트·탭바·CTA·FAB)은
`PageMain` 밖이라 넓은 화면에서 열을 벗어난다.

**새 토큰 값 0개.** 별칭 두 줄만 열었다. 포커스 링 두께·오프셋 토큰은 **안 만들었다** — 소비처가 전역
규칙 하나뿐이라 `08f6652` 이 걷어낸 "정의만 되고 쓸 길 없는 토큰" 과 같은 종류가 된다.

## 인시던트

1. **`transition-colors` 가 모든 버튼의 포커스 링을 140ms 페이드인시키고 있었다.**
   그 유틸리티의 property 목록에 `outline-color` 가 있다. `color` 도 있어서, 시세를 자기 자신에 갖는
   요소가 이 클래스를 쓰면 등락 색이 적↔청으로 바뀔 때 중간에 무채색을 지나 "보합" 으로 읽힌다.
   **어느 에이전트도 혼자서는 못 잡았다** — 디자이너는 워크트리에 `node_modules` 가 없어 빌드 CSS 를
   못 쟀고, 프론트는 링이 안 보이는 쪽이라 목록을 볼 이유가 없었다. 어휘 쪽에서 "링은 전이하지 않는다"
   를 명시하고 나서야 그 목록을 확인할 이유가 생겼다.

2. **죽은 유틸리티 클래스 둘로 FAB 이 중복 충전을 막는 시트를 덮고 있었다.**
   `InProgressDialog` 이 쓴 `z-overlay` 는 Tailwind v4 에 z 테마 네임스페이스가 없어 **클래스가 아예
   생성되지 않는다** (번들에 `.z-overlay{` 0건). 시트에 z-index 가 없었고 radix 포털의 DOM 순서에만
   기대고 있었다. 동시에 `AiFloatingOverlay` 는 `z-40` 을 손으로 박아 사다리(floating 20 < overlay 30)
   위로 올라갔다. **한쪽만 고치면 여전히 FAB 이 이긴다.**
   이 종류는 **빌드·타입체크·린트를 전부 통과하고 클래스 이름이 그럴듯해 리뷰도 통과한다.**
   `frontConvention.md` §12.7 에 규약으로 남겼다.

3. **`focus:outline-none` 진단이 두 번 뒤집혔다.** 처음엔 "링을 죽인다"(특정도 기준), 실측 후
   "효과가 없다"(캐스케이드 레이어가 명시도를 이긴다). 죽은 코드지만 **거짓말을 하므로** 지웠다.

4. **KIS 진단이 세 번 틀렸다.** ① "샌드박스가 비표준 포트를 막는다" → 내 Bash 도 같은 맥에서 돈다.
   ② "포트 문제" → 같은 호스트의 443 도 안 닿았다. ③ "핫스팟으로 바꿨다" → 유선(싸피 801)이 기본
   경로라 트래픽이 그대로 나갔다. **결론: 싸피 유선망이 `210.107.75.32` 를 통째로 막는다.**
   `www.koreainvestment.com:443` 은 되고 API 호스트만 안 된다.

5. **`.env` 를 `source` 로 읽다가 계좌번호가 에러 메시지에 노출됐다.** `=` 뒤 공백 하나 때문에 shell 이
   값을 명령으로 실행하려 했다. 이후 shell 을 거치지 않고 파싱한다.

6. **에이전트 스레드가 꼬여 오배송·오귀속이 반복됐다.** 디자이너가 이미 떠 있는 프론트를 못 찾아
   하나 더 띄웠고, 그 중복 에이전트가 발신자를 두 번 잘못 짚었으며, 여러 에이전트가 서로의 주장을
   잘못 귀속했다. **손해는 중복 작업뿐이었지만, 같은 결함 셋을 두 브랜치가 독립적으로 고쳤다.**
   결론이 같았던 것은 운이다.

7. **에이전트의 실측이 `git` pathspec 오용으로 거짓 음성을 냈다.** `cwd` 가 `frontend/` 인데 pathspec 을
   `-- frontend/src/styles/` 로 줘 없는 경로를 봤고, 빈 출력을 "안 건드렸다" 로 읽었다.
   **"실측했다" 가 "옳게 측정했다" 를 뜻하지 않는다.**

## 교훈

- **DOM 측정은 "맞다" 를 알려주지 "보인다" 를 알려주지 않는다.** 아트보드 70개를 크기·토큰·폰트로
  전부 검증하고도 프레임이 안에서 떠 있는 것을 못 잡았다. 처음 눈으로 본 순간 3초 만에 드러났다.
  **렌더해야 보이는 결함은 렌더해야 보인다.**
- **회의는 서로가 못 보는 자리를 교환할 때 값이 나온다.** 디자이너는 빌드를 못 했고 프론트는 볼 이유가
  없었다. `transition-colors` 는 둘 중 누구도 혼자서는 못 잡았을 결함이고, **어휘 쪽이 "링은 전이하지
  않는다" 를 못 박은 것이 프론트에게 그 목록을 볼 이유를 만들었다.**
- **빌드·타입체크·린트를 다 통과하는 결함이 따로 있다.** `z-overlay`·`bg-bg-overlay` 는 클래스 이름이
  그럴듯해 리뷰도 통과한다. **컴파일된 CSS 를 봐야 보인다.**
- **진단이 틀렸다면 몇 번이든 정정한다.** 이번 스프린트에서 내 진단이 KIS 3회, 포커스 링 2회 뒤집혔다.
  매번 정정한 것이 옳았지만, **더 나았을 것은 처음에 대조군을 같이 재는 것이었다** — 같은 호스트의
  443 을 재봤으면 "포트 문제" 를 한 번에 건너뛰었다.
- **"실측했다" 가 "옳게 측정했다" 를 뜻하지 않는다.** pathspec 하나가 어긋나 빈 출력이 나왔고 그것이
  "변경 없음" 의 증거로 읽혔다. **빈 결과는 도구가 옳게 겨눠졌는지부터 의심한다.**
- **에이전트를 여럿 띄우면 배선이 일이 된다.** 중복 기동·오배송·오귀속이 반복됐고 같은 결함을 두
  브랜치가 따로 고쳤다. **누가 무엇을 소유하는지 문서가 한 가지로 말해야** 한다 — 이번엔 토큰
  소유권 문장이 두 갈래라 실제로 두 에이전트가 같은 파일을 건드렸다.
