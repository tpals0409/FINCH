# Sprint 3 — 토대

_날짜: 2026-09-03_

## 목표와 그 목표를 버린 이유

승인된 계획은 **백엔드 원장**이었다 — 계좌·충전·보유·내역과 원장 불변식 테스트.

착수 직전에 세 가지가 드러났다.

1. `./gradlew build` 가 이 머신에서 돌지 않았다 (JDK 21 부재)
2. **CI 가 없었다.** PR #1~#5 가 전부 검증 없이 머지됐다
3. 계획이 "원장은 외부 의존 0" 이라 적었지만 `GET /account`·`GET /portfolio` 가 현재가를 요구했다

**돈이 오가는 코드를 검증 장치 없이 쓰는 것보다 장치를 먼저 만드는 게 맞다고 판단했다.** 원장은 Sprint 4 로 넘긴다.

## 결정 사항

### D1. 백엔드를 Kotlin 으로 옮긴다

토스가 Kotlin/Spring 이라는 사실에서 출발했지만(세민이 "토스는 Go" 로 알고 있었고 확인 결과 아니었다) 결정 근거는 다른 것이다.

**널 가능성을 스키마 제약과 타입으로 잇는 것** 하나다. 나머지(Lombok 제거, `data class`)는 삶의 질이다.
그리고 **72파일 4,224줄은 이 코드베이스가 앞으로 가질 가장 작은 크기**였다.

Go 를 기각한 이유: 이 도메인에 Go 모양의 문제가 없다. CRUD + 트랜잭션 산술 + 팬아웃이고,
Go 가 유리한 자리는 시세 STOMP 팬아웃 하나뿐인데 그것 때문에 언어를 바꾸는 건 남는 장사가 아니다.

**이관의 계약은 "행동 변화 0" 이었고 테스트 99개가 그 증거다.** 널 가능성의 기준을 Java 코드가 아니라
Flyway 스키마로 잡았고, 그 대조에서 **스키마와 어긋난 자리 셋**이 나왔다 — 검증 실패 `detail` 에 null 이
실릴 수 있던 것, `AiRelayException.message` 가 계약상 필수인데 nullable 이던 것, DTO 가 영속화 전
엔티티 id 를 싣던 것. **셋 다 동작은 정상이고 타입만 열려 있어 테스트로는 드러나지 않았다.**

### D2. 파이프라인을 CI 와 CD 로 가르고 게이트를 건다

`ci.yml`(검증)과 `images.yml`(빌드·GHCR·gitops 태그 갱신)을 분리했다. 실패의 의미가 다르기 때문이다.

분리의 대가로 **master push 에서 둘이 병렬로 돌아 "코드가 틀렸다" 가 "배포됐다" 를 못 막았다.**
`wait-for-ci` job 으로 게이트를 걸었다. `workflow_run` 을 쓰지 않은 이유는 그러면 `dorny/paths-filter` 가
diff 기준을 못 잡아 서비스별 변경 감지가 깨지기 때문이다.

**values.yaml 에 들어가는 태그는 커밋 SHA 다.** 가변 태그를 쓰면 매니페스트가 그대로인데 이미지만
바뀌어 ArgoCD 가 변화를 보지 못한다. GitOps 가 성립하지 않는다.

### D3. 멱등성 레코드를 Postgres 에 둔다

`backConvention` 은 Redis 를 제안으로 적어 뒀다. 기각한 이유가 둘이다.

**감수 수준이 다르다.** `RefreshTokenStore` 가 Redis 를 고른 전제는 "재기동 = 전원 재로그인, 감수한다"
였는데, 멱등성 키가 날아가면 재시도 중이던 요청이 **두 번째 충전·두 번째 주문**이 된다.

**그리고 원자성.** 레코드가 Redis 에 있으면 "원장을 썼다" 와 "그 키를 완료로 표시했다" 가 다른 저장소의
다른 커밋이다. 둘 사이에서 죽으면 원장에는 행이 있는데 키는 미처리로 남는다.

설계의 핵심: **판정의 출발점이 조회가 아니라 예약 INSERT 의 성패다.** 조회 후 INSERT 는 두 요청이
동시에 "없음" 을 볼 수 있지만 PK 는 정확히 하나만 통과시킨다.

### D4. 역할 에이전트 6종을 만들고 전원 회의를 연다

위임할 때마다 같은 것을 프롬프트에 다시 적고 있었다. `.claude/agents/` 에 `backend`·`frontend`·`ai`·
`infra`·`librarian` 을 추가했다 (`designer` 는 기존).

그리고 **여섯을 읽기 전용으로 소집해 각자 자기 파트를 읽게 했다.** 물은 것은 넷이고 마지막이 핵심이었다 —
**"아직 아무 문서에도 없는 위험."**

이 회의가 이 스프린트에서 가장 값어치 있는 두 시간이었다. 아래 인시던트가 전부 거기서 나왔다.

### D5. S0-1~7 은 열세 항목이 아니라 하나였다

`lab.ssafy.com` 17건 · "8/26 결정 회의" 7군데 · `featureSpec` S0-1~7 · `apiSpec` §13 7건 ·
`contracts` 미확정 5건이 **전부 회신할 수 없는 팀 하나를 가리켰다.**

분류하니 **실제로 정할 게 하나였다.** S0-2·S0-6·S0-7 은 이미 구현돼 돌고 있었고, S0-4 는 확장 범위,
S0-1 은 KIS 앱키 없이 원천적으로 모르지만 구조가 수치와 무관해 아무도 안 막힌다.
**S0-3(`stale` 허용 시간)만 남았고 15초를 제안했다** — `apiSpec §5.6` 관계식의 하한 10초의 1.5배다.

## 인시던트

**전부 회의에서 나왔고, 전부 빌드·테스트·CI 가 잡지 못하는 종류였다.**

1. **등락률 100배** — `formatSignedPercent` 가 `×100` 인데 `primitives.ts` 는 "곱하지 않는다" 를 브랜드
   타입으로 선언해 뒀다. **파라미터가 브랜드 없는 `number` 라 `Percent` 가 조용히 통과했다.** 같은 날
   문서에서 같은 오류를 고쳤는데 코드는 그대로였다 — **사서는 문서를 보고 프론트는 코드를 본다.**

2. **AI 어댑터의 사용자 간 데이터 유출** — `@lru_cache` 싱글턴이 `self._user_id` 에 사용자를 담고
   곧바로 `await` 했다. 두 요청이 겹치면 **A 가 B 의 포트폴리오를 받는다.** 지금 잠들어 있고
   **깨우는 조건이 정확히 백엔드가 `/internal/v1` 을 여는 것** — 다음 스프린트다.

3. **k8s 에서 뜨지 못하는 파드 셋** — nginx 443 이 없는 인증서를 가리켜 `nginx -t` 실패, frontend 가
   `runAsUser: 1000` 을 상속해 `/var/cache/nginx` 권한 거부, backend `ServiceMonitor` 가 CRD 없이 렌더돼
   Application 전체 Degraded. **아무도 렌더·실행을 해본 적이 없어서 아무도 몰랐다.**
   클러스터를 먼저 세웠으면 빨간 Argo 앱 셋을 디버깅했을 것이다.

4. **Opus 에이전트 넷 동시 실행이 세션 한도를 태웠다.** 이어 529 가 세 번 났다. 살아남은 작업이
   워크트리에 남아 있어 이어받았지만, **커밋 안 된 작업만 위험했다.** 이후 중간 커밋을 지시했다.

5. **워크트리 하나를 에이전트 둘이 공유하다 브랜치가 바뀌었다.** 손실은 없었지만 원인이 내 지시였다 —
   "새 브랜치를 파라" 를 써놓고 워크트리가 공유된다는 걸 뒤늦게 알렸다.

6. **지운 파일의 참조 아홉 곳이 남았다.** 디자이너가 색 화석을 지웠는데 `AiFloatingOverlay.tsx` 와
   `ia.md` 가 인용하고 있었다. **오늘 하루 종일 고친 "반쯤 지운 것" 을 우리가 다시 만들었다.**

## 교훈

- **자기 코드를 읽는 사람에게 물어야 나온다.** 회의 전 나는 결함 0건을 알고 있었고, 여섯에게 "아직 아무
  문서에도 없는 위험" 을 묻자 10건이 나왔다. 전부 실측 근거가 있었다. **파트를 나눈 값어치가 위임이
  아니라 이 자리에 있었다.**
- **문서를 고치는 것과 코드를 고치는 것은 다른 일이다.** 등락률 100배를 낮에 문서에서 고쳤는데 저녁에
  코드에서 다시 찾았다. 계약을 고쳤으면 그 계약을 구현한 자리를 함께 grep 한다.
- **렌더하거나 실행해야 보이는 결함이 따로 있다.** 오늘 셋을 그렇게 잡았다. "빌드가 통과한다" 는
  "뜬다" 를 뜻하지 않는다. 클러스터가 없다는 것이 매니페스트를 렌더하지 않을 이유가 되지 않는다.
- **타입으로 막을 수 있으면 문서로 부탁하지 않는다.** 브랜드 타입을 도입해 놓고 파라미터를 `number` 로
  두면 브랜드가 그 자리에서 무력화된다. 규칙을 지켜달라고 적는 것과 컴파일러가 지키는 것은 다르다.
- **미확정 목록은 분류부터 한다.** 일곱 중 실제로 열린 건 하나였다. 나머지는 이미 구현됐거나, 범위
  밖이거나, 아무도 안 막고 있었다. **막혀 있다고 믿는 것과 실제로 막힌 것은 다르다.**
- **에이전트에게 중간 커밋을 시킨다.** 커밋 안 된 작업만 날아간다. 한도와 서버 장애는 예고 없이 온다.
