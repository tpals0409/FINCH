# Sprint 13 — 폰에서 눌러보고 고치는 하루

_날짜: 2026-09-09 ~ 2026-09-10_

## 목표

원래 목표는 Sprint 12 이월(#103 · #78 · #90 · #115 · #93 · 005930 · price_daily 첫 실행)이었다.
**착수 직후 Leo 가 우선순위를 바꿨다** — iOS 앱을 실기기에 올리는 것이 먼저고, 이유는 폰으로 직접
눌러봐야 QA 가 빨라지기 때문이다. 그 뒤의 스프린트는 계획서가 아니라 Leo 의 손끝에서 나왔다.

이 문서는 계획을 지운 자리에 실제로 한 일을 적는다. 원래 범위는 「이월」에 그대로 남긴다.

## 결정 사항

### D1. iOS 실기기가 최우선이다

시뮬레이터가 아니라 Leo 의 폰이다. 근거는 속도다 — 화면을 직접 만져야 "여기가 어색하다" 가 나오고,
그게 한 번에 하나씩 고쳐진다. 실제로 이 스프린트의 커밋 절반이 그렇게 나왔다.

### D2. "네이티브" 는 OS 기본 UI 가 아니다

드롭다운을 `<select>` 로 두고 "이미 네이티브다" 라고 답했다가 정정받았다. Leo 가 말한 네이티브는
**우리 앱만을 위한 디자인**이다. 기존 `finch-sheet-*` CSS 를 재사용한 바텀시트로 다시 만들었다.
용어가 같아도 가리키는 것이 다를 수 있고, 그럴 때 먼저 묻는 편이 싸다.

### D3. price_daily ↔ 핫셋 불일치는 B안

거래 가능 종목과 시세 적재 대상이 어긋나 "산 종목의 시세 이력이 없다" 가 났다. 선택지는
① 적재를 종목 마스터 전체로 넓히기 ② 거래 가능 목록 하나를 두고 양쪽이 그것을 보기.
**API 호출 제한이 있으니 ②** 로 정했다 (Leo). `ai_tradable` · `/internal/v1/ai/price-universe` ·
`ingest.prices` 대상이 한 목록이 됐다.

### D4. 뉴스 브리핑은 가공을 재사용하고 최종만 개인화한다

종목별로 뉴스를 모아 가공한 결과를 DB 에 두고, 사용자 포트폴리오에 따라 마지막에 한 번 더
LLM 으로 개인화한다. 사용자마다 같은 기사를 다시 읽히지 않으면서 답은 개인 것이 된다 (Leo).

### D5. LLM 게이트웨이 주소는 코드 기본값이 아니라 배포 설정이다

저장소에서 기관 식별자를 걷어내다 발견했다 — `ai/app/core/config.py` 의 `gms_base_url` 기본값이
**운영에서 실제로 쓰이는 주소**였다. 봉인 스크립트가 키만 봉인해 `ai-secrets` 에 그 항목이 없었다.
gitops 로 먼저 옮기고(#19) 코드 기본값을 비웠으며, 비면 클라이언트 생성 시점에 실패시킨다.
주소가 없을 때 상대 경로로 조용히 붙는 것보다 기동에서 터지는 편이 낫다.

2. **배포가 안 붙었다고 두 번 틀리게 판정했다**: 한 번은 코드 스플릿된 청크 대신 엔트리 번들을
   grep 했고, 한 번은 Tailwind 임의값(CSS)을 JS 에서 찾았다. **엔트리 → 청크 목록 → 해당 파일**
   순서로 가지 않으면 "없다" 가 쉽게 나온다.
3. **에이전트 셋이 이미 머지된 브랜치 위에 커밋했다**(프론트 1 · AI 2): 그중 하나는 nginx 의

   #124 로 다시 열었다. **항상 최신 master 에서 브랜치를 판다**를 규칙으로 세웠다.

## 교훈

- **계획서와 사용자의 손끝이 다르면 손끝이 이긴다.** 이 스프린트의 계획 범위는 거의 안 쓰였는데
  결과는 더 좋았다. 계획은 우선순위가 없을 때의 기본값이지 사용자를 이기는 문서가 아니다.
- **지우기 전에 그것이 서술인지 설정인지 본다.** 주석처럼 생긴 한 줄이 운영 값이었다. 문자열이
  코드에 있다는 사실은 그것이 문서라는 뜻이 아니다. 지우는 변경일수록 소비처를 먼저 센다.
- **잘린 관측을 전체로 옮겨 적지 않는다.** `head -10` 이 붙은 grep 은 "10곳" 이 아니라 "최소 10곳"
  이다. 특히 **"없다"·"N개다" 같은 전수 주장**은 자를 때 가장 쉽게 틀린다.
- **빌드가 EXIT 0 이어도 산출물을 연다.** 래퍼의 종료 코드는 안쪽 도구의 종료 코드가 아니고,
  통과한 테스트가 그 코드를 산출물에 실었다는 증거도 아니다 (#98 과 같은 모양이 또 나왔다).
- **남의 실행 환경은 그쪽에서 나온 값으로만 판정한다.** 이번에도 가설 두 개가 실측으로 뒤집혔다.
  추론으로 메운 남의 상태는 빠르게 그럴듯해지고 느리게 틀린다.
