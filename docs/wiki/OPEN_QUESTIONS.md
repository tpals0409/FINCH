# 아직 안 정해진 것

이 페이지는 미결정 항목의 값이나 개수를 보관하지 않는다. 원본의 상태표가 바뀌어도 새 계약 표면이 생기지 않도록, 질문의 종류별로 확인할 위치와 대조 순서만 기록한다.

## 전체를 훑는 순서

1. [S0 결정 정리의 분류 표](../spec/s0-decisions.md#분류--일곱-중-실제로-정할-것은-몇-개인가)에서 `S0-*` 항목이 실측·제안·확정 중 어디에 놓였는지 확인한다.
2. 백엔드 API나 주문·시세 동작에 영향을 주면 [백엔드 API 명세의 확정 필요 항목](../api/apiSpec.md#13-확정이-필요한-항목)을 대조한다.
3. 프론트가 다른 파트의 답을 기다리는 질문이면 [프론트 계약 현황의 미확정 표](../../frontend/docs/contracts.md#3-미확정)을 본다.
4. 화면 구성이나 라우트가 달라지는 질문이면 [프론트 IA의 미확인 항목](../../frontend/docs/ia.md#7-미확인-항목)을 함께 본다.

같은 질문이 여러 표에 있으면 한쪽의 문구만 보고 닫지 않는다. 각 표는 제품 정책, 백엔드 계약, 프론트 의존성, 화면 영향이라는 서로 다른 관점을 기록한다.

## 질문별 원본

| 질문의 종류 | 상태를 확인할 원본 | 최종 내용을 기록할 원본 |
|---|---|---|
| `S0-*`의 현재 상태와 남은 실측·승인 | [S0 결정 정리](../spec/s0-decisions.md) | 문서가 각 항목에서 지정한 소유 원본 |
| 원래 Sprint 0 결정 항목과 제품 영향 | [기능 명세의 Sprint 0 표](../spec/featureSpec.md#12-sprint-0에서-확정해야-하는-항목-개발-착수-전-필수) | [기능 명세](../spec/featureSpec.md) |
| 백엔드 API에서 아직 합의가 필요한 동작 | [백엔드 API 명세의 확정 필요 항목](../api/apiSpec.md#13-확정이-필요한-항목) | [백엔드 API 명세](../api/apiSpec.md) 또는 새 ADR |
| 프론트가 기다리는 크로스파트 계약 | [프론트 계약 현황의 미확정 표](../../frontend/docs/contracts.md#3-미확정) | 표가 가리키는 백엔드·AI 원본과 [프론트 계약 현황](../../frontend/docs/contracts.md) |
| 화면 구성과 라우트에 남은 질문 | [프론트 IA의 미확인 항목](../../frontend/docs/ia.md#7-미확인-항목) | [프론트 IA](../../frontend/docs/ia.md)와 해당 계약 원본 |
| AI 서비스 계약 자체의 미결정 | [AI 서비스 API 명세의 결정 필요 항목](../api/aiApiSpec.md#5-요약--결정이-필요한-항목) | [AI OpenAPI](../../ai/docs/openapi.json)와 [AI API 명세](../../ai/docs/api-spec.md) |

## 상태를 닫을 때

- 결정 전에 각 원본의 기준일과 최근 변경 이력을 확인한다.
- 구현 사실을 근거로 삼을 때 AI 스키마는 [AI OpenAPI](../../ai/docs/openapi.json), 백엔드 계약은 [백엔드 API 명세](../api/apiSpec.md)를 우선한다.
- 합의가 끝나면 결정을 소유 원본에 반영하고, 그 원본을 참조하는 상태표에서도 미결정 표시를 해소한다.
- 과거 스프린트 ADR은 고치지 않는다. 결정이 바뀌었다면 새 ADR이나 현재 명세에서 이전 기록을 링크한다.
