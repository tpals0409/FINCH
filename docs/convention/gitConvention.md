# Git 컨벤션

브랜치·커밋 메시지 규칙의 원본이다. 이 문서와 루트 `CLAUDE.md` 가 어긋나면 여기가 기준이다.

> SSAFY 팀 시절의 팀 프로세스 절(이슈 기반 브랜치명 `S1241AS1-23-auth`, "MR은 작성자 본인이
> 머지하지 않습니다", MM 리뷰 요청)은 1인 ver2 에서 성립하지 않아 걷어냈다.
> 커밋 규칙은 그대로 유효해서 남긴다.

## 브랜치

```
<type>/sprint-<N>-<설명>
```

예: `feat/sprint-3-order-idempotency` · `docs/sprint-3-doc-audit`

**스프린트 번호가 들어가야 한다.** ADR 에서 그 스프린트의 커밋을 되짚는 유일한 방법이다.

- `master` 에 직접 커밋하지 않는다. 항상 브랜치 + PR + squash 머지
- 1브랜치 n커밋 1PR
- 머지 후 브랜치는 지운다

## 커밋 메시지

### 1. 형식

`<타입>: <제목>` 또는 `<타입>(<scope>): <제목>`

- **이모지를 붙이지 않는다**
- 콜론 앞에 공백을 넣지 않는다. 콜론 뒤에만 공백 한 칸
- 타입은 영어 소문자

```
O: feat: 회원가입 기능 추가
X: ✨feat: 회원가입 기능 추가
X: feat : 회원가입 기능 추가
```

| 타입 | 의미 |
|---|---|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 수정 |
| `style` | 코드 formatting, 세미콜론 누락 등 코드 자체의 변경이 없는 경우 |
| `refactor` | 코드 리팩터링 |
| `test` | 테스트 코드 추가·수정 |
| `chore` | 패키지 매니저 수정, 그 외 기타 수정 (예: `.gitignore`) |
| `design` | CSS 등 사용자 UI 디자인 변경 |
| `comment` | 필요한 주석 추가 및 변경 |
| `rename` | 파일·폴더 이름을 바꾸거나 옮기는 작업만인 경우 |
| `remove` | 파일을 삭제하는 작업만 수행한 경우 |
| `!BREAKING CHANGE` | 커다란 API 변경의 경우 |
| `!HOTFIX` | 급하게 치명적인 버그를 고쳐야 하는 경우 |

AI 파트는 어느 모듈을 고쳤는지 드러나도록 scope 를 붙인다. 목록은 `ai/CLAUDE.md` 에 있다.

### 2. 제목

- 한글로 쓴다. 완료형(`추가`·`수정`·`변경`)
- 영문 기준 50자 이내
- **끝에 마침표를 붙이지 않는다**

### 3. 본문은 필요할 때만

**제목만으로 충분하면 본문을 쓰지 않는다.** 대부분의 커밋은 한 줄로 끝난다.

본문이 필요한 경우는 왜 그렇게 했는지가 제목만으로 안 드러날 때, 주의할 부작용이 있을 때다.
쓸 때는 제목과 빈 행으로 분리하고 **무엇을 했는지가 아니라 왜 했는지**를 적는다.
무엇을 했는지는 diff 가 말한다.

```
# 좋음 — 제목만으로 충분
docs: 기능 명세서 v2.1 추가

# 나쁨 — 본문이 제목을 반복할 뿐
feat: 회원가입 기능 추가

- 회원가입 기능 추가
```

여러 항목이 있으면 글머리 기호로 나눈다.

### 4. 한 커밋에 한 가지

리팩터링과 기능을 섞지 않는다. 너무 많은 문제를 한 커밋에 담으면 되짚을 수 없다.

### 5. CLI 에서 여러 줄 쓰기

기본은 한 줄이다.

```bash
git commit -m "feat: 회원가입 기능 추가"
```

본문이 꼭 필요할 때만 개행해서 이유를 적는다. 쌍따옴표를 닫지 말고 개행하면 된다.

```bash
git commit -m "fix: 주문 중복 체결 방지

동시 요청 시 잔액 검증이 통과되어 이중 체결되던 문제.
멱등성 키로 중복 요청을 차단함."
```

## PR

- PR 본문은 [`.github/PULL_REQUEST_TEMPLATE.md`](../../.github/PULL_REQUEST_TEMPLATE.md) 가 채운다
- CI 가 녹색이어야 머지한다
- squash 머지. 머지 후 브랜치를 지운다
