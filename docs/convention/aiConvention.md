# [AI] AI 파트 개발 컨벤션

- 작성일: 2026-08-20
- 관련 문서: [Git 컨벤션](./gitConvention.md) · [PR 템플릿](../../.github/PULL_REQUEST_TEMPLATE.md) · [AI 서비스 API 명세](../api/aiApiSpec.md)

## 이 문서의 범위

AI 파트는 담당자 1명이 저장소의 `ai/` 하위만 소유합니다. 팀 공통 규칙을 그대로 따르되
**팀 기본과 다르게 운용하는 지점**만 여기에 적습니다. 다르게 가는 걸 각자 알아서 하면
나중에 리뷰·머지에서 매번 설명해야 하므로, 합의가 필요한 것만 팀 문서로 올립니다.

커밋 scope, 디렉터리 구조, worktree 부트스트랩, 적재 순서, 문서 생성 파이프라인처럼
`ai/` 안에서만 통하는 규칙은 [`ai/CONTRIBUTING.md`](../../ai/CONTRIBUTING.md)에 두고
여기로 올리지 않습니다. 팀 합의 대상이 아닌 걸 팀 문서에 올리면 읽을 게 늘기만 합니다.

---

## 1. 쓰기 범위

AI 파트는 **`ai/` 안에서만** 수정합니다. `backend/`, `frontend/`, `infra/`, 저장소 루트는
읽기 전용입니다. 루트 설정 변경이 필요하면 팀에 요청합니다.

글로벌 `docs/` 중 **AI 파트가 작성한 문서**는 AI 파트 소유이며 직접 수정합니다.
현재 해당하는 문서는 아래와 같습니다.

| 경로 | 내용 |
|---|---|
| [`docs/api/aiApiSpec.md`](../api/aiApiSpec.md) | 프론트·백엔드가 연동하는 AI API 계약 |
| `docs/convention/aiConvention.md` | 이 문서 |

다른 파트가 작성한 문서는 내용이 틀려도 직접 고치지 않고, 소유자에게 정정 문안을 넘깁니다.

## 2. 브랜치와 MR — 팀 기본과 다른 부분

| 항목 | 팀 기본 ([gitConvention](./gitConvention.md)) | AI 파트 |
|---|---|---|
| 브랜치 단위 | 이슈 단위 | **에픽 단위** |
| MR 시점 | 이슈 개발 완료마다 | **에픽 범위가 끝났을 때 1회** |
| 스토리 티켓 | 이슈 = MR | 티켓은 만들되 MR 은 열지 않음 |

```
S15P21A101-<에픽번호>-<에픽명>      예) S15P21A101-4-ai-service
```

**이유**: 담당자가 한 명이고 소유 경로가 `ai/` 로 격리되어 있어, 스토리 단위 MR 은
팀 리뷰 부담만 늘리고 리뷰 실익이 거의 없습니다.

**대신 브랜치가 오래 사는 부담을 이렇게 줄입니다.**

- 작업 중 주기적으로 `origin/master` 를 브랜치에 반영
- 스토리별로 커밋을 분리해 리뷰어가 단위로 읽을 수 있게 함
- **Squash 하지 않음** — 스토리별 커밋이 리뷰 단위라 뭉개면 읽을 수 없음
- MR 본문에 포함된 스토리 티켓과 설계 문서 절 번호를 적고, 팀 조치가 필요한 항목을 따로 뽑음

머지는 **리뷰한 팀원이 누른다**, 머지 후 원격 브랜치 삭제 — 팀 규칙 그대로입니다.

## 3. 다른 파트가 알아야 하는 원칙

| 원칙 | 의미 |
|---|---|
| **계산은 Engine, 설명은 AI** | LLM 은 어떤 수치도 스스로 만들지 않습니다 |
| **파생 지표를 백엔드에서 받아 쓰지 않음** | 원장만 읽고 AI 파트가 직접 계산합니다. 받아 쓰면 화면마다 값이 어긋납니다 |
| **타 파트 의존은 읽기 하나** | 기존 원장 조회 API 의 읽기 권한(`/internal/v1`)뿐. 신규 화면·계산 로직을 다른 파트에 요청하지 않습니다 |
| **AI 서버는 외부에 노출하지 않음** | 사용자 식별을 백엔드 신뢰 헤더로 받습니다. 배포 조건은 [API 명세 §4](../api/aiApiSpec.md) 참고 |
